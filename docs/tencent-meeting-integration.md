# 接入腾讯会议的可行性评估

> 结论先行：**技术上能接，但 oc-gov 现在接 API 有 90% 的概率卡在账号资质上，不是卡在代码上。**
> 建议分两段做：**A 段（会议号 + 入会链接，零资质，今天就能做完）** 与 **B 段（调 API 自动建会，等资质确认）**。
> 本文所有腾讯会议侧的事实都标了来源；`core/` 侧的判断基于本仓库现有代码。

## 一、先把「接入」这句话拆开

「oc-gov 接入腾讯会议」至少有四种含义，成本差两个数量级：

| 想要的效果 | 需要什么 | 成本 |
| --- | --- | --- |
| 会议通知里带**会议号/入会链接**，参会人点链接进会 | 一个固定的腾讯会议链接 | 半天，零资质 |
| 确认建会后**自动在腾讯会议里开一场**，回填会议号 | 腾讯会议开放平台应用 + 企业版权限 | 3-5 天 + 资质审批 |
| 会后**自动拉录制/转写/纪要** | 云录制权限 + 录制管理接口 | 依赖 B 段，另加权限 |
| 页面里**内嵌开会**（Web SDK） | 前端引 SDK + 企业资质 | 与「工作台」定位冲突，不建议 |

下面按「A 段 / B 段」展开。

## 二、B 段的三个硬门槛（这是决定性的）

### 1. 免费版和个人版根本调不了

【事实·已核实】腾讯会议官方「创建会议」接口文档（`meeting.tencent.com/support-doc-detail/532`）原文：

> 企业版2.0、商业版2.0、教育版2.0账号：购买高级账号数 ≥ 50 个：10 次/月/高级账号，总限频为（高级账号数 × 10）次/月；
> 购买高级账号数 < 50 个：2 次/月/高级账号，总限频为（高级账号数 × 2）次/月。
> 原 SaaS 版企业版、原 SaaS 版教育版账号：购买虚拟会议室数不足 10 个，**无法使用该接口**。

这条的意思很直白：**没有企业版付费账号，接口直接不可用**。政务单位一般采购了企业版，但「高级账号数 ≥ 50」这一档要查合同。

### 2. 建会限频低到不像生产接口

即使够 50 个高级账号，`POST /v1/meetings` 也只有 **10 次/月/高级账号**。一个 100 个高级账号的企业，一个月总共 1000 次建会。

这意味着：**「每次确认建会都自动调 API」这个设计在配额上是撑不住的**。日常例会必须走 A 段（固定链接），API 只留给少数重要会议。

> 注意：限频是**按接口**算的。修改会议、取消会议、查详情是另外的接口，配额宽松得多（具体看各自文档）。所以「改期/取消同步」反而比「建会」容易做。

### 3. userid 是自然人，不是单位

【事实·已核实】创建会议接口的 `userid` 必填，语义是「企业唯一用户标识」（对接 SSO 的员工 ID，或调用「创建用户」接口时传的 userid）；`invitees` 是同一套 userid 数组，且**仅商业版和企业版可邀请参会者**。

而 oc-gov 现在的模型是**单位**不是人：`attendees` 是「市住建局」「市发改委」，`host` 是职务（「常务副市长」）。两者之间没有映射表 —— `core/people.py` 里的人是「系统里的角色」，不是腾讯会议里的账号。

所以 B 段还有一个前置工程：**单位 → 具体经办人 → 腾讯会议 userid** 的映射。而政务场景里让每个局的经办人都绑到同一个企业租户下，本身是个管理动作，不是代码问题。

## 三、和项目现有底线的冲突，以及怎么处理

oc-gov 有三条硬约束，接外部会议平台会同时压到两条：

| 现有约束 | 接腾讯会议后的冲突 | 处理方案 |
| --- | --- | --- |
| **只出草稿不直接建**（`README` 会议助手一节） | 自动建会产生真实外部副作用，且外部没有「改字段」的退路 | 顺序必须是：**先本地落库拿 `MT2026-0001`，再调 API，成功回填会议号；失败标 `online.status=failed` 给重试入口**。反过来先建外部会再落库，一旦落库失败就留下孤儿会议 |
| **模型不能自己写**（工具面 3 个只出草稿） | 不能在 `core/agent.py` 加「建腾讯会议」工具 | 建会只发生在 `/api/meetings` 与 `/api/meetings/<id>/online` 两条人工触发的写口，**不进模型工具面**。模型的 `draft_meeting` 仍然只出草稿卡 |
| **纯标准库、零第三方依赖、不联网也能跑** | 要发 HTTPS 请求 | `urllib.request` + `hmac`/`hashlib` 签名足够，不加依赖；模式默认 `off`，不配就走原来的行为，`tests/smoke.py` 在没有网络的环境下仍然全绿 |
| **凭据不进可被模型读的地方** | 要存 SecretId / SecretKey | 只走 `config/local.env` 的 `OCGOV_TMEET_*` 环境变量（已 gitignore），**不进 `data/models.json`**，也不出现在任何工具返回值里 |

另外要记审计：`audit.user_event(..., action="meeting.online_create", target=MT id, payload={meeting_code, ok})`。这是外部副作用，出了事要能追到谁点的。

## 四、A 段：会议号 + 入会链接（建议先做这一段）

**不调任何 API**，只把「线上参会」当成会议的一个属性存下来。

### 数据

`ledger.create()` 增加一个 `online` 字段（跟着 `place` 走，不进索引、不影响日程）：

```python
"online": {
    "provider": "tencent",      # 预留，将来接别的平台
    "join_url": "",             # https://meeting.tencent.com/dm/xxxx
    "meeting_code": "",         # 9 位会议号，便于电话拨入/手输
    "password": "",             # 4-6 位，可空
    "source": "manual",         # manual | api
    "external_id": "",          # B 段用，API 返回的 meeting_id
    "status": "none",           # none | ready | failed
    "error": "",
    "created_at": "",
}
```

### 改动清单

| 文件 | 改什么 |
| --- | --- |
| `core/meeting/ledger.py` | `create()` 收 `online` 参数并落库；`brief()` 带出（列表页要显示会否线上）；`delete()` 不删外部会（A 段没有外部会，B 段见下） |
| `core/meeting/notice.py` | 会议通知加「线上参会」段：会议号 + 链接 + 密码。缺链接时**不编**，写「另行通知」（沿用现有 `warnings` 机制） |
| `core/notify.py` | `_meeting_notes()` 会前 60 分钟提醒的正文里带 `join_url` —— 这是最有用的一处，领导收到提醒就能直接点进去 |
| `app/web/index.html` | 建会草稿卡加「线上会议」输入（链接/会议号/密码），落库后详情页显示一键复制 |
| `tests/smoke.py` | 加断言：`online.status == "ready"` 时通知正文必须含会议号；缺链接时必须落到 `warnings` 而不是编一个 |

**为什么先做这个**：零资质、零风险、当天可用；而且 B 段做完之后这一层不用改 —— API 建会成功只是把 `source` 从 `manual` 变成 `api`、把字段填满。

## 五、B 段：调 API 自动建会

### 鉴权

两条路，选 **OAuth2.0**（AK/SK 的 HMAC-SHA1 多次签名已经没有优势了，且官方文档现在两种都列）：

```
POST https://api.meeting.qq.com/v1/oauth/token
  grant_type=client_credentials&client_id=...&client_secret=...
→ access_token（缓存，过期前 5 分钟刷新）
后续请求：Authorization: Bearer <token>，另需 X-TC-Key: <client_id>
```

> 【待核实】OAuth2.0 的 `client_id` / `client_secret` 与旧版 `AppId` / `SdkId` / `SecretId` / `SecretKey` 的对应关系，各文档说法不一致。**接入前必须拿你账号后台的实际字段对一遍**，不要照网上的文章抄。

### 建会

```
POST https://api.meeting.qq.com/v1/meetings
{ "userid": "<主持人会议账号>", "instanceid": 1, "subject": "<标题>",
  "type": 0, "start_time": "<unix秒>", "end_time": "<unix秒>",
  "settings": {"mute_enable_join": true, "auto_in_waiting_room": false} }
→ meeting_id / meeting_code / join_url / password
```

`userid` 从哪来？两种做法：

1. **单主持人模式**（推荐先做）：环境变量 `OCGOV_TMEET_HOST_USERID` 配一个固定的会务账号，所有会都挂在它名下、由它当主持人。避开了「单位→人」的映射难题，代价是主持人不是真正的领导（腾讯会议里显示的是会务账号）。
2. **按人映射**：`core/people.py` 每人加 `tmeet_userid`，缺的这个字段就退回模式 1。要做这个，先得有「单位→经办人」的通讯录，那是第 2 条「下一步」里权限那块的活儿。

### 改期 / 取消

`plan` 落库后能改时间（现有草稿卡改时间 = 新建一条，不是改）。接入后应该允许 `PATCH /api/meetings/<id>` 改时间并同步外部会 —— 但这一步要先给本地台账加「改字段」的能力（README 明确说过「会议没有改字段的接口，建完只能删」，这是当时的刻意选择）。**建议单独一轮做，不要和建会混在一起。**

### 失败怎么办

| 情况 | 处理 |
| --- | --- |
| 网络超时 | `status=failed`，`error` 存原因，本地会照常存在（不影响日程和提醒），给「重试建会」按钮 |
| 402/配额超限 | 同上，但文案要写清「本月建会配额已用完，请手动填会议号」——**不能让人以为是自己填错了** |
| 建会成功、回填落盘失败 | 最坏情况：外部有会、本地没号。所以回填要在同一把 `store.update()` 里，且失败时把 `external_id` 记进审计日志，人工能从腾讯会议后台找回来 |
| 取消本地会 | 有 `external_id` 就先调取消接口，成功再删本地；调不通就**拒绝删除**并说明原因 —— 静默留一个没人管的会是更坏的结果 |

## 六、明确不做的

- **不在页面里内嵌开会**（Web SDK）：工作台是「看全局 + 问一句」的地方，内嵌会议厅会把它变成另一个客户端。
- **不给模型加建会工具**：外部副作用必须有人点确认。`draft_meeting` 保持只出草稿。
- **不做「会后自动拉录制转写」**：依赖云录制权限，且转写文本进知识库需要过引文闸/数字闸，那是另一条链路（现有 `core/meeting/extract.py` 三道闸只针对「粘进来的纪要」，不是对录制稿）。要做得单独立项。
- **不引第三方 SDK**：`tencent-meeting-sdk` 之类都是 Python 包，和「核心标准库即可跑」定位冲突。签名和 HTTP 用 `hmac` + `urllib` 手写，约 80 行。

## 七、需要你确认的三件事

1. **账号版本**：是腾讯会议企业版/商业版/教育版哪一档？高级账号数多少？（决定 B 段能不能做）
2. **主持账号**：能不能拿到一个固定的会务账号 userid？（决定用「单主持人模式」还是「按人映射」）
3. **先做哪段**：如果资质一时确认不了，建议直接做 A 段，它不依赖任何腾讯会议权限，且不会被 B 段推翻。

## 八、工作量估算（不含资质审批等待）

| 段 | 内容 | 规模 |
| --- | --- | --- |
| A | ledger / notice / notify / 前端 / smoke | 约 250 行改动，1 个工作日 |
| B | 新增 `core/meeting/online.py`（签名 + token 缓存 + 建会/取消）、落库编排、重试写口、审计、配置项 | 约 400 行，2-3 个工作日 |
| B+ | 改期同步、按人映射 | 各 1 天，且依赖通讯录/权限那一轮 |
