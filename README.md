# oc-gov · AI 市长工作台

> ⚠️ **开发中**：功能与接口仍在变动，不建议用于生产环境。11 个指标里只有 GDP 接了公开发布的真实年度值（2025 年 1746.29 亿元），其余是构造的演示值；没有对接任何实时政务数据接口。

一屏把「问一句」和「看全局」放在一起：左栏自然语言问数，右侧全市罗盘 + 五块板块看板，底部督办预警条。**每个数字都能点开查口径、责任部门、报表和披露日期。**

三条贯穿全项目的底线，后面所有设计都是从这里推出来的：

1. **数字不经过模型** —— 模型只输出「问的是哪个指标、哪一期」的查询计划，数值由接口返回后原样拼装。
2. **模型只能查、不能办** —— 工具面只有三个只读插件，内置工具（读写文件、执行命令、联网）全禁，写操作一律不进工具清单。
3. **写操作认身份** —— 所有写接口在一张登记表里过闸，表外的写路径一律 403。

## 快速开始

```bat
start-all.cmd        :: 一键启动：先起本地模型（可选）再起工作台，就绪后自动开浏览器
run.cmd              :: 只起工作台 → http://127.0.0.1:8090
run.cmd 8091         :: 换端口
run-llm.cmd          :: 只起本地模型服务（llama.cpp，127.0.0.1:8099，可选）
```

- **首次启动在控制台打印一条登录口令**（只打印一次，落盘存 pbkdf2 哈希）。想固定就设 `OCGOV_PASSWORD` 环境变量，它是权威值
- **不登录也能浏览，但写操作一律被拒**并留审计痕迹。登录后按身份判定，越权会被挡下并说明理由
- 核心标准库即可跑（Python 3.11+），**不联网也能运行**。三个可选依赖都是「装了自动升级、不装静默降级」：`fastembed`（语义向量检索，不装退回 bigram 关键词）、`octop-memory`（跨会话记忆）、`octop-harness`（插件引擎，不装则由 `core/toolhost.py` 补加载器）
- 模型：点右上角胶囊配置（或 `/#models`），支持多 provider × 多模型、一键测连通性。**不配也能跑**：问数退回规则解析，罗盘和预警不受影响
- 首次启动从 `config/local.env` 自动导入一条 provider；自动生成 8 条示例督办台账到 `data/oversight-state.json`（删掉重启即回基线）

**想看完整的会议与问数效果**，跑一次演示数据脚本：

```bat
python seed_demo.py            :: 写入 3 场演示会议，知识库 19 → 26 条
python seed_demo.py --force    :: 清掉重建；不加参数时已有演示数据会跳过
python seed_demo.py --dry-run  :: 只打印将要做什么，不落盘

python seed_docs.py            :: 写入 3 个分类库、7 份政策文件（上传文档那一路的演示数据）
python seed_docs.py --force    :: 清掉重建；内容与台账/会议咬合，搜「停车难」「入河排污口」能同时命中两种来源
```

`data/` 不进版本库（里面有会话和模型配置），所以刚 clone 下来会议库是空的 —— 指标口径 11 条、督办台账 8 条是代码内置的，只有会议记录依赖 `data/meetings.json`。不跑脚本，问「上次开会定了什么」会答「没有相关记录」，那不是坏了，是还没数据。

## 能证明什么

- **问数和罗盘用同一套指标字典** —— 问「规上工业增速」和看那张卡片，数字必须一致，不会出现「页面写 8.9、助手说 8.5」
- **每个数字可溯源** —— 点卡片给出数值、同比、走势、口径定义、责任部门、报表名、披露日期、接口地址、使用注意
- **预警不是写死的文案** —— 来自督办台账实时扫描（逾期 / 今日到期 / 临期 / 签收超时 / 停滞）
- **多轮能用指代** —— 「那上个月呢」「换成区县看」不用重复指标名：历史按模型窗口回灌原文
- **能写闭环** —— 签收 / 反馈 / 提交办结 / 确认办结 / 退回 / 催办全走状态机守卫，被拒的操作不落任何数据
- **材料是装配出来的** —— 骨架、分段、每处数字和出处都由代码拼，模型只写「下一步」一节且只能用手上的数；每节底下挂依据（台账经过 / 议定原文 / 口径 / 上传文档段落），出手前可一键审校，能导出真 .docx
- **公文能开文种** —— 请示和通知的骨架写死在代码里，事实从勾选的台账 / 指标按编号重取，模型只写「缘由段」且要过数字闸、单位闸、套话闸；文号留空不代编，成文日期可改
- **检索返回原文** —— 知识库（含上传文档）返回逐字原文和出处，模型不参与检索，没有转述的机会
- **提醒只搬运不制造** —— 从台账状态、会议时间、指标披露派生，每条能点回出处；同一件事每天只提醒一次
- **写操作认身份不认前端** —— 后端签发 session，`WRITE_POLICY` 登记表 + 默认拒绝，每次写与每次越权都进 append-only 审计

## 没证明什么

写汇报材料前必看。

| # | 缺口 | 现状与原因 |
| --- | --- | --- |
| 1 | **基本没有真实数据** | 只有 `GDP_TOTAL` 接了 2025 全年 1746.29 亿元（+5.0% 可比价，来源《2025 年溧阳市国民经济和社会发展统计公报》）；其余 10 个指标及全部月度走势是构造值。证明「链路能通」，不证明「数据可信」 |
| 2 | **权限只做了最小一层** | 已有：登录、三档角色、写接口总闸门、督办与知识库读收窄、审计。缺：身份不从干部系统同步（`core/directory.py` 是手写映射）；读收窄未覆盖指标/会议/日程/提醒；前端不做按钮级隐藏；无改口令页面；审计无查询界面；**演示态下个人数据可被冒充**（会话/关注/收藏的写口保留匿名放行，身份取自 `X-Person-Id`）。个人工作台的身份切换是演示用的，不是权限 |
| 3 | **没有指标中台** | 指标注册、口径变更、同源同口径校验是另一套工程，这里假设那张字典表已存在 |
| 4 | **民情焦点是假的** | 三条固定条目，真实系统要接 12345 工单聚类 |
| 5 | **叫醒止于本机** | 提醒有规则表、跨天去重、站内信、桌面通知，外发代码也写完了，但**默认一个通道都没配**，责任单位收不到。不是没做，是没填凭证 |
| 6 | **送达无回执、无按单位路由** | 企微机器人只管发、不回执；一个 webhook 对应一个群，全市提醒进同一个群；外发没有「谁批准」这一层，所以不提供 `force` |
| 7 | **没有响应式** | 最小宽度按 1180 设计，更窄出现横向滚动 |
| 8 | **约会议只能建、通知只能成文** | 不能改期（只能删了重建）、不知道谁参加；会议通知能成文并导出到桌面，但**不发送**——发给哪个群、谁收到，系统不知道也不记录；没有人员日历和会议室资源，撞车只能提示「同一时间段还有另一场会」 |
| 9 | **存储只支持单进程** | `data/*.json` 的写锁是进程内的。多 worker 会互相覆盖，要多人用得换 SQLite/PostgreSQL（`core/store.py` 是唯一要改的地方） |
| 10 | **材料得先有人转成文本** | `.xlsx` / `.docx` 能读；PDF / 图片 / 扫描件不收，`.xls` / `.doc` 也读不了（旧版二进制）。材料**只在当轮生效**，不落盘、不进知识库 |
| 11 | **不做录音转写、不做 AI 生成纪要** | 本机没有 ASR；会议记录原文是输入，不是模型产物 —— 让模型写纪要再让模型抽事项，等于自己出题自己判卷 |
| 12 | **开文种只管「写得对不对」** | 请示 / 通知的体检查要素齐不齐、文种对不对、一文一事、结语与附注日期，**不查所请事项有没有政策依据、要不要法核、要不要上会** —— 那属于合法性审查，规则做不了。只做两个文种（批复要引用来文文号、函要对接外单位，都缺可靠事实源）；文号不代编、签发日不定、不盖印、不上报；生成的是**草稿**，送签前必须有人逐句看过并认账 |

## 问数与对话

**一次问答的链路**：`meetplan` / `chitchat` 前置判断 → 模型出查询计划（JSON）→ 程序取数 → 程序拼答案 → 可选专家解读。模型没有第二次说话的机会，也就没有编数字的入口。

**工具面收口**（`core/harness.py`）。插件引擎装上后，模型手上只允许三个只读工具；三层闸一起生效：

| 闸 | 做法 |
| --- | --- |
| 内置工具全禁 | `_BUILTIN_TOOLS_DISABLED` 静态封死 `read_file` / `write_file` / `execute` / `browser_use` / `task` 等 —— `data/models.json` 存着 API key，读出来念一遍就是泄露，不需要写权限 |
| 写工具按前缀摘 | 插件工具名以 `advance_` / `urge_` / `close_` / `send_` 等开头的一律摘掉，被摘的名字进 `/api/health` 的 `blocked_tools` |
| 底线锁 | `BASELINE_TOOLS`（`query_metric` / `list_metrics` / `scan_oversight` / `search_knowledge`）所在插件不可停用，按**工具名**锁而非插件 id —— 目录可以改名，工具名是契约 |

底线锁是双保险：`set_enabled` 拒绝停用并抛 `BaselineLocked`（接口 403），就算手改 `plugins.json` 写成 `false`，构造 agent 时也会把它从 disabled 里摘回来。页面开关变灰挂「底线」标只是给人看的。

**上下文预算按窗口比例算，不写死条数**。`chat.history_budget()` 取一半窗口给历史，另一半留给 system prompt、输出和误差；窗口来自模型配置的 `context_window`，没填按 8192 兜底（**宁小勿大**：高估会把 prompt 撑爆、请求直接被拒，低估只是少带几轮）。参考材料最多占窗口 25%，占用还要从历史预算里扣。

**回灌的是原文，含数值** —— 模型看到自己上一轮真正说过的话，指代才有落点。数值防线在输出侧，不在上下文侧：数字出现在上下文里可以接受，出现在新生成的结论里不行。

**流式用 SSE**，推真实阶段 `start` → `plan` → `done`，不是把答案按字切开的假打字机（模型只输出结构化计划，本来就没有可读正文流）。

**能写的那类问句单独前置**。「约个会」在指标字典里一定匹配不到，不前置就会变成「没有对应的指标」——用户提了个能办的需求，系统回一句它办不了。寒暄同理，但用**整句匹配**（去标点后必须恰好是寒暄），所以「你好，9 月工业增速多少」照常走问数；且不调模型，本地 27B 一次推理 2-5 秒，为「你好」跑一遍只会让人以为卡了。

**界面上三个细节**：

- 答案底部一行 `3 次模型调用 · 1.2s · 上下文 8/12 轮 · 参考 2 个附件`，悬停给分段解释 `系统 1112 + 历史 1700 = 2812，窗口 8192（34%）`。只报一个「历史 1700」会让人误以为多问几轮很贵，真正的大头常常是那个 1100 的固定指标目录
- 导出是重新拼的 Markdown（问题 / 结论 / 指标表含出处 / 依据 / 专家解读 / 材料对照 / 可信度脚注），不是截屏转文字；历史会话走同一份构造逻辑
- 会话内查找（`Ctrl+F`）只滚动 + 临时描边 1.6s，**不改写文本节点** —— 高亮要拆开文本重拼 DOM，而复制、折叠、收藏、口径胶囊的事件全挂在那棵树上

**切会话不打断正在跑的那一轮**：给容器挂 `turnId`，返回时只写进「这就是它的那个容器」；容器不在文档里就只落库不渲染，切回来再补。不禁止切换是有意的 —— 一轮可能跑十几秒。

## 参谋团（专家解读）

输入框上方一个下拉：总参谋 + 六位专业参谋（经济运行 / 招商引资 / 重大项目 / 社会治理 / 民生保障 / 生态环境），单选；最后一项「参谋团」一次叫上全组（最多 3 位）。不选人时这一行是空的，要取消就再点一次。

**名单不写死在代码里**：每位参谋是 `experts/<id>/expert.md`，加一位就是加一个目录。设置 →「专家」可编辑，删掉的目录移进 `experts/_removed/` 留底。输入框打 `/`（全角 `／` 也认）弹出同一层菜单，与下拉**同源同出口**：同一个 `/api/experts`、同一个 `selectExpert()`。三个细节：只在行首认（`投资/工业` 是正常写法）、全角必须认（中文输入法上屏是 U+FF0F）、组词中的 Enter 不抢（`e.isComposing`）。

**专家不取数**。数值、口径、出处仍由 `ask.py` 拼出来，专家只补一段「怎么看」。若让专家自己查数，同一场会里经济参谋说 8.9%、民生参谋说 9.1%，谁也说不清该信谁。

**数字闸**：解读里出现阿拉伯数字或百分号 → **整段丢弃**并注明原因，不做「修正」。指标名自带的数字（如「12345 群众诉求按期办结率」）先剔掉再校验。判定是纯函数 `_has_forbidden_number()`，可单独断言。传给专家的输入也不含数字，只有指标名和方向信号。

**参谋读知识库，但只读自己域内那几条**：`index(person, domain)` 先按身份收窄、再按域收窄。指标按代码归属（一个指标只归一位参谋，否则同一份口径被两个域各引一半）；事项/会议按 `units` 列表归属（看主办也看协办，否则「常务副市长主持、生态环境局参加」的会三个域都读不到）。

- 单位名要归一才对齐：去括号补充说明、去行政级别前缀、查简称表。不做归一不是报错，而是域里一条都读不到，界面显示「本域内无记录」，看着像库里空着
- 判**前缀**不判包含：按包含判，经济参谋的「市统计局」会把「国家统计局本市调查队」带进来，民生参谋管的失业率就跑错门
- 问的指标一个都不属于他的域 → 直接 `skipped`，卡片写「本轮问的不是你关注的事」，**不调模型**（省一次 token，也省一次编造的机会）。`skipped` 和「模型没给出来」样式必须不同
- 每张卡下方列依据，能点回台账或会议记录；没有依据时明写「本域内暂无记录」。老消息没有 `refs` 字段就不显示这一行 —— 不能让旧数据假装检索过

**不做合并总结**：召唤三位 = 同一个问题、同一组数字、三段角度看，各自独立。合并得再调一次模型，那次调用不产生新信息，只多一次编数字的机会。

## 参考材料（附件）

回形针选文件 → 浏览器读成文本 → 只交给 **planner**，不进答案、也不进专家团。模型用材料判断「问的是哪个指标、哪一期」，数值仍只来自指标接口。

- **纯文本**：`txt / md / csv / tsv / json / log / yaml / xml`（UTF-8 猜不准自动换 GBK）
- **`.xlsx` / `.docx`**：字节 `POST` 到 `/api/attachments/parse`，服务端解析回文本。**不在浏览器里解** —— 两份实现迟早在某张表上分叉，而且是「一边 7.2%、一边 0.072」这种最难发现的分叉
- **明确拒绝**：PDF / PPT / 图片 / `.xls` / `.doc`，拒绝时说明原因。收下一个读不出内容的 PDF，比当场拒绝更糟。格式判断看包里的部件，所以 xlsx 改名成 .docx 也认得出

| 限制 | 值 | 为什么 |
| --- | --- | --- |
| 份数 | 5 | 再多就不是「参考一份材料」 |
| 单份字数 | 12000 | 一份月度报表正文的量级 |
| 合计字数 | 30000 | 超过这个数，材料会把问题和指标目录一起挤出 prompt |

前端截一遍、后端再截一遍（`/api/ask/stream` 是公开接口，curl 塞 200MB 进来前端挡不住）。

**解析里两个真正难的点**：Excel 存的不是看到的（`7.2%` 存 `0.072` + 数字格式，`2026-09-30` 存序列号 `46295`，且 1900 系统有 1900-02-29 补丁，序列号 ≥ 60 要减一天），所以要**按数字格式还原显示值**；Word 里有三种「存在但看不见」的节点（`w:del` 修订删除、`w:vanish` 隐藏文字、`w:instrText` 域代码），只走「人会看到的那条路」并报「跳过 N 处隐藏文字」。这两处不处理，材料对照的原文闸会静默失效 —— 功能看着没坏，其实坏了。

### 材料里的数字：A / B 两档

材料写「7.2%」、库里是「5.6%」，怎么办？

- **A 档（已上锁）**：材料里的数字**不进答案**，不进 headline、不进 facts、不进专家解读。一旦 headline 出现一个来自上传文件的数，那句话就再也核不了 —— 文件在用户电脑上，服务端只有截断后的临时文本
- **B 档（已落地）**：检测到材料有本轮指标的数值时，答案下方**并列**一块对照，两个数各自带出处（`材料 7.2% 摘自《9月统计月报.csv》` / `指标库 5.6% 市统计局《本市统计月报》2026-09`），用户自己判断差在哪（通常是「累计」和「当月」）

配得上才显示，四道闸：指标闸（`metric_code` 必须在字典里）、**原文闸**（数值必须在材料原文里逐字符命中，`7.2` 不算命中 `7.25`）、意图闸（只在单指标取值/走势场景配）、同指标闸（材料说的必须是本轮主指标）。任何一道不过就静默丢弃 —— 错配比不显示更糟，也绝不能让模型编一个「材料值」冒充核对过。

## 材料助手

**它不是「AI 写材料」。** 汇报材料里最贵的错误不是句子不通，而是把「1—9 月累计」写成「9 月单月」、把「预计」写成「实绩」。模型看到的是字符串，区分不了这些；写进上报材料后基本没人回头复核。所以反过来做：**骨架、段落、每个数字、每处出处都由代码装配，模型只写最后一节。**

| 骨架 | 章节 | 来源 |
| --- | --- | --- |
| 工作汇报 | 指标运行 / 重点工作 / 会议落实 / 下一步 | 指标字典 + 督办台账 + 会议记录 |
| 会议落实材料 | 会议信息与交办明细 / 指标 / 披露情况 / 下一步 | 一场会议的记录 + 台账 |
| 督办通报 | 统计 / 逾期与临界清单 / 分单位办理 / 下一步 | 督办台账 |

叫「会议落实材料」而不是会前材料：系统里只有已经开过的会，硬做会前材料只能靠人手填议程，又是一份和台账对不上的时间表。这个骨架回答的是「这个会定的事，现在办到哪了」。

- **每处数字带出处**：指标表最后一列是「数据来源」，页脚按部门列报表名与披露日；督办明细带台账编号。测试里有硬断言：材料里的指标值必须与问数接口逐字节一致
- **模型只能写第四节**：输入是排好序的事实清单，输出只允许 `{"next": "..."}`。三道闸（≤ 260 字、不得出现清单外的数字、不得新增事项或单位），任何一道不过整段丢弃并写明原因，退回规则文本。模型写了，纸面注释会变成「本节由模型根据上文事实撰写」—— 不冒充，也不甩锅
- **不存档**：材料不落盘，一旦存起来就会出现「文件里的数和台账不一致」。要留存就导出 Markdown / Word 或打印

### 导出 Word

纸面是给人看的，交上去的是文件。「下载 .docx」出来的是真 Word，不是改了扩展名的 HTML：A4，页边距上 37 下 35 左 28 右 26 毫米；正文仿宋_GB2312 三号、行距固定 28.5 磅，标题方正小标宋二号，一级标题黑体，页脚「— 1 —」式页码；红头公文连红色机关名、发文字号、红色反线一起排。**纯标准库拼 OOXML**（`core/docxgen.py`：zip + XML），不引 python-docx，与全项目「不装第三方也能跑」同一条口径。

**换格式不换事实**：导出不是「再生成一次」，而是把纸面那份 meta / blocks 原样排版。冒烟测试里有一条断言，比的是 docx 回读出来的数字集合与 Markdown 的数字集合是否相等。

难点不在写文件，在样式映射：`w:sz` 是半点（三号 16 磅 → 32）、行距是 twips、`w:pPr` 子元素顺序错了 Word 不报错、只静默丢格式。换算和顺序约束集中写在 `core/docxgen.py` 顶部。

### 依据：写的时候就把原文摆在手边

每一节下面一行灰字「依据 N 条」，点开是这一节背后存的原文。**四样东西性质不同，取法也必须不同**：

| 依据 | 怎么取 | 为什么不能靠检索 |
| --- | --- | --- |
| 台账办理经过 | 按事项编号取最近一笔事件 | 编号唯一，取出来不可能「差一点」 |
| 会议议定 | 按会议编号取议定事项原文 | 同上；纪要原文本身就是引文 |
| 指标口径 | 按指标代码取口径里容易被误读的那几句 | 口径是字典里的固定字段，检索只会把它排个序 |
| 上传文档段落 | 真的走检索 | 上传的政策文件没有编号挂在某条台账上 |

**只有最后一行是「检索」，前三行是「查表」。** 把已有的结构化关系做成检索看起来更时髦，但会引入一个本不该存在的失败模式 —— 台账里明明有这条事项，检索却因为措辞没对上而没召回。

依据**不上纸、不进模型、不进导出**：默认折叠，展开也在正文之外，打印和导出都不带走。也不塞进写「下一步」那一段的上下文 —— 模型会把原话改写一遍，而原话的价值就在于它没被改过。理由是它属于工作底稿，不属于公文。上传文档那一路额外卡一道 0.40 下限（降级检索只有覆盖率、没有绝对阈值）：实测「停车难专项治理」能召回海绵城市文件（0.067），这种必须挡掉；库空时如实没有，不拿一段似是而非的政策原文凑数。

### 出手之前先审一遍

工具栏「审校」把这份材料回查一遍，结果贴在纸面右边的侧栏里，点一条就跳到出问题的那一节。**审校不让模型参与判断** —— 让模型「通读一遍说哪里不对」，同一个问题问两次会给出两套意见，还会给一堆似是而非的建议把真问题淹掉，所以判断全是规则和回查：

| 查什么 | 怎么查 | 典型报错 |
| --- | --- | --- |
| 数字 | 叙述里每个数字都要落在事实池里（指标真值、台账统计、期次、结构计数）；指标表逐格与口径表当期值比对 | 「12.7 在指标库、台账、会议记录里都查不到」 |
| 引用 | 督办行回查台账编号，状态 / 责任单位 / 时限要与台账此刻一致；会议与指标要能查到记录 | 「DB2026-0027 的状态写的是已办结，台账当前是办理中」 |
| 过期 | 台账统计数与本刻重算的统计数比 | 「材料写逾期 3 项，台账此刻是 5 项」 |
| 体例 | 章节序号、ISO 日期、单位称谓、半角标点、承诺性表述 | 「出现承诺性表述『坚决、务必』」 |

**关键在「重取一遍」。** 审校不是拿纸面自己当标准，而是从指标库和台账重新取数 —— 所以它能发现前面几层都发现不了的那类错：**材料是旧的**。生成之后有人在台账里办结了一件，纸面不会自己变，但审校会报「台账已变动」。这种错最难查：它看起来是自己系统出的，也就最容易被直接交上去。

两条断言把这件事固定住了：装配出来的材料必须能过审（过不了说明审校在瞎报），改坏一处必须被抓住（抓不住就只是装饰）。八类故意改错在 `tests/smoke.py` 里逐条验过。**分值只是让人有个数**：硬错 10 分、建议 3 分、提示 1 分，扣到 0 为止，有硬错直接判「不可出手」；它不承担「几分算合格」这种判断 —— 那该由看材料的人定。

### 明确没做

- **不查错别字、不查语句通顺**。那需要词表和句法分析，规则做不干净，模型做不可复现
- **不改材料**。审校只报问题，不改写、不自动替换 —— 政务材料里的每一处改动都得有人认账
- **不写讲话稿、不写工作总结**。那类文字没有可核对的数字锚点，写完也没法验证对错
- **不提供公文模板编辑**。版式写死在 CSS 和 `docxgen` 里：让人自己调格式，很快就会调出四不像
- **纸张不跟随深色主题**。它是一张纸，屏幕上看到的必须和打印出来的一致

## 开文种：请示与通知

材料助手写的是**已经发生的事**；这一块写的是**还没发生的事** —— 一份要送签的请示或通知。

这类文能自动化，不是因为模型会写公文，而是两件事恰好成立：**结构是法定的**（请示就是「缘由—事项—结语」，通知就是「依据—事项—要求—结语」，没有第二种写法，所以骨架写死在代码里，模型改不了也不给它改的机会）；**事实来自登记过的地方**（要办的事在督办台账，要讲的指标在口径表，依据的会议在会议台账 —— 勾一个编号，正文里那句话就有了出处）。

| 文种 | 骨架 | 默认主送 | 结语 | 必备项 |
| --- | --- | --- | --- | --- |
| 请示 | 缘由 / 事项（一）（二） | 常州市人民政府 | 妥否，请批示。 | 联系人 + 电话（附注） |
| 通知 | 缘由 / 事项 一、二、/ 工作要求 | 各镇（区）、市各委办局、市各直属单位 | 特此通知。 | 抄送（涉及多部门时） |

**模型只写「缘由段」**，这是全流程唯一的措辞自由 —— 缘由段是背景交代，不承担数字责任。写出来仍要过三道闸，任何一道不过就整段丢弃、退回规则文本并如实说明原因：**数字闸**（只能用事实清单里出现过的数字，不许自己算比例、算天数、算差额）、**单位闸**（提到了材料里没有的单位就丢 ——「市生态环境局已同意」这种句子比数字错更危险）、**套话闸**（出现「高度重视」「狠抓落实」就丢，这类词删掉不损失任何信息）。请示事项、通知事项、工作要求全部来自人填的要素或勾选的台账，模型碰不到。

**系统不编文号。** 发文字号由发文登记簿管理，序号取决于本年度已经发到第几号，系统里没有这本簿子，编出来的号一定是错的 —— 所以默认留空，纸面显示「溧政〔2026〕___号」，体例检查里提示去登记簿取号。成文日期默认取今天、可以改：签发日是领导定的。勾选的台账事项如果什么都没填，会自动变成事项条款（少打几遍字），但每一句都带台账编号、能点回去；同一件事不在缘由段里再说一遍 —— 说两遍，读的人会以为是两件事。

**体例检查复用同一个审校侧栏**，查的不是数字，是「这份文现在能不能签」：要素（「标题里的事由还是空的」「没有主送机关，这份文不知道发给谁」）、文种（「请示事项 4 条，违反一文一事」「请示的结语要提出请求」）、附注（「请示要在成文日期下方注明联系人和电话」）、体例（「成文日期 2026-11-07 不是『2026年11月7日』的写法」「用了套话『高度重视』」）。硬错 12 分、建议 5 分、提示 1 分，有硬错直接判「不可出手」；报的每一条都能点到那一段 —— 纸面上每段带 `data-blk`，点问题就滚过去。

**出口**：屏幕上那份和导出的 .docx 是**同一份数据** —— 导出时把前端手上的 `meta` / `doc` 原样回灌，服务端只排版、不重新装配。重新装配会让文件里的措辞和屏幕上的对不上，而这份稿子是要打印出来送签的。

**明确没做**：不做「命令」「批复」「函」（批复要引用来文文号，函要对接外单位，都缺可靠事实源；硬做出来只能靠人手填，那和直接用 Word 没区别）；不代拟文号、不定签发日、不盖印（这三件事都在系统外面，代劳就是造假）；不存档（和材料同一立场：窗口里的草稿，存下来就会出现「文件里的说法和台账对不上」）；不自动上报（生成到此为止，发出去的那一步必须有人按）。

## 知识库

**一个页面，两个来源**：系统自己产出的四类记录（指标口径 / 督办事项 / 会议议定 / 会议记录），和人上传的政策文件、报告。两者共用同一套向量化（`core/embedding.py`）和同一条边界——返回的永远是原文带出处，模型不参与检索。

以前它们是两个名字、两个入口：系统记录叫「知识库」在顶栏，上传文件叫「资料库」藏在头像菜单里。数据从来不重合，但**用户只认「库」这一个概念**——看完顶栏那个清单页，会以为库就这些，找不到自己传的那份政策文件。所以合并了：入口只留顶栏「知识库」，**上传、建库、删库也都在这一页**（右上角「＋ 上传文档」），不再有单独的「上传文档」弹窗和头像菜单项；`data/rag.json`、`core/rag.py` 这些内部名字没动。

**知识库有两个入口：对话里的兜底，和一个只读的清单页**。「上次开会定了什么」「环保局那件事办到哪了」在指标字典里匹配不到，以前会被当成「未注册指标」拒答 —— 而那恰恰是最容易回答的一类问题。索引每次检索时从现有数据现算（几十到几百条，成本可忽略），所以台账刚改完就能搜到，也不用处理缓存失效。

**清单页（顶栏「知识库」/ `/#knowledge`）**左边目录、右边原文，五类条目按「指标口径 → 督办事项 → 会议议定 → 会议记录 → 上传文档」排：`browse()` 是它专用的出口，**不设阈值、不打分** —— 检索不敢给低分条目，是因为它要当答案的依据；翻目录漏一条，就会让人以为库里没东西。搜索框走的是同一个端点（带 `q` 就切到 `search_in`），分类 chips 两种模式都生效，所以「只在会议里找提到环保的」一句话就能表达。预览只给四样东西：出处（部门 / 报表 / 期次 / 编号）、正文、原文引句、**能点回台账或会议**的按钮 —— 知识库不做第二套操作界面，要办事还得回原处。上传文档的预览换成**阅读视图**，不套四格：文件头（文件名、所属库、大小、上传时间、字数、章节数）+ 章节正文，正文自己滚，长文件的最后一章也能滚到顶部。**章节是按标题行切出来的**（markdown `#`、`第一章`、`一、`、`（一）`、`1.`），标题和第一句写在同一行的（「一、总体目标：到 2028 年底……」）会拆开，否则那段正文会被标题吞掉。检索时先按文件去重（一篇命中十块只列一次），点开文件再把命中块映射到章节：顶部给「命中 N 段，分布在 M 个章节」和可点的章节导航，正文自动滚到第一个有内容的正文章节，命中词高亮；语义命中时正文里可能没有原词，这时额外给一块「命中片段」引用原文。**文件名也单独算一路命中**（`name_hit`，整串或二字组覆盖率 ≥ 0.7），用户打全名时那份文件排在前面。底部给「删除这份文件」和「管理分类库」——文件是这一页自己的东西，删除不必再跳出去。`#knowledge=关键词` 可以连检索一起分享。

**编号检索不看阈值**（`_id_hit`）。把 `DB2026-0033` 贴进搜索框，语义余弦只有 0.2 上下、字面覆盖率也低，按阈值走会被整条挡掉，表现为「明明有这个编号却搜不到」。编号是唯一键，对上就是对上；会议号命中时，这场会的议定事项一起放行（问会议号的人，多半就是要看这场会定了什么）。

**检索两档，向量优先、bigram 兜底**：

- 装了 `fastembed` → 本地 ONNX 语义检索（`BAAI/bge-small-zh-v1.5`），权重走 `specific_model_path` + `local_files_only` **直接读本地缓存，全程不联网**，包括首次。刻意不走默认下载路径（那会在内网静默外联 HuggingFace）。**权重必须由人提前放进缓存目录**（探测顺序见 `core/embedding.py`），找不到就返回 None 退回 bigram，程序自己不会去下
- 没装 → bigram 二字组覆盖率 + 三层加权（术语命中 +0.55 / 单位命中 +0.30 / 编号命中 +1.0），两道防误伤：二字组 ≥ 3 个时至少命中 2 个；「事项」「单位」「情况」这类模板词不参与
- 同义词**双向都试、取最高分**：「环保局」要能匹配「生态环境局」，但台账里写的就是「市发改委」，替换成长名反而命中不了

**余弦阈值不是一个数，而是一段灰度区**。0.55 按指标类问句标定，对模糊的事项类问句会误伤 —— 实测「上次开会定了什么」0.540（该命中）、「进出口数据」0.528（只落在「数据」这个通用词上，不该命中），两者只差 0.012。所以 0.50~0.55 要求第二个独立信号佐证：问句二字组覆盖率 ≥ 0.40 才放行（上例 0.50 vs 0.25，分得开）。承认的事实是：单一相似度分在短查询上信息量不够，需要两路信号互证。代价是两个常量换 embedding 模型要重新标定。

**介入时机**：拒答之前先查知识库；寒暄更早一步；问句里有「办到哪 / 进展 / 定了什么 / 谁在办」且确有督办或会议记录时，**不让问数答数值**（「环保局那件事办到哪了」曾被答成「空气质量 86.5%」—— 答非所问但形式上完全正常，这是最坏的一种错）。纯数值问题不受影响。

**上传文档**（顶栏「知识库」→ 右上角「＋ 上传文档」）：收 md/txt/csv/tsv/json/html/docx/xlsx，复用 `docparse`；按 800 字符 + 120 重叠切块；控制面进 `data/rag.json`，原文落 `data/rag_files/`，每个库一个 SQLite 向量索引（标准库自带）。上传面板里可以建库、删库、选文件入库；单份文件在它的预览底部删。写权限：建库/上传/删除要登录；演示态下读不收窄 —— 所以它在知识库清单里**不受身份收窄**（系统记录那四类按身份收窄，这是两个来源唯一的行为差异）。

检索时**按文档去重**：一篇文件命中十块，清单里列十遍没有意义，只留分最高的那块。合并排序时两路分数不同源 —— 系统记录是「余弦 + 硬信号」（编号精确命中能加到 1.0），上传文档是纯余弦 —— 所以系统记录天然靠前。这是想要的次序：台账/口径是现成的答案，文件是要读的原文。

**上传文档的召回是两个信号取并集**：向量分 ≥ 0.55（语义相关，允许换说法），或者问句的字面原样落在这段里（不看分）。只留向量一路的话，800 字的片段会把短查询稀释掉 —— 实测「双随机」对确实写了这三个字的那一块只有 0.296，「消防通道」0.337，「预付卡」0.408，全被 0.55 挡在门外，表现就是「文件里明摆着写着，搜不到」。字面对上就是字面上对，这和编号检索不看阈值是同一条道理：确定的证据比阈值可靠。反向的边界也钉住了：只放宽这一路，别的不相关内容仍然不返回（smoke 里有正反两条断言，改坏了会红）。

## AI 日程

只读汇总，不是日历。回答两件事：今天必须做什么、下一件在几号。**不做月历网格** —— 14 天里绝大多数格子是空的，一屏放不下，又看不出「下一件是几号」。

| 来源 | 变成什么 | 时间从哪来 |
| --- | --- | --- |
| 会议记录 | 会议 | `held_at`（已结束的不排） |
| 督办 · 待签收 / 待审核 | 今天要处理 | 状态机 |
| 督办 · 已逾期 | 已逾期（今天，注明原时限） | `deadline` + 剩余天数 |
| 督办 · 停滞 | 补报进展（今天） | 超过 7 天没有新进展 |
| 督办 · 未到期 | 办结时限（落在 deadline 那天） | `deadline` |
| 指标字典 | 数据披露 | `DISCLOSURE_DAY`（每月 10 日披露上月） |

- **同一天只出现一次，不同天各算各的义务**：今天要签收、20 号要办结，就是两条 —— 两个义务日，不是重复
- **逾期不挂在过去的日期上**：归到今天，说明里写「原定 X 日办结，已逾 N 天」
- **身份口径与工作台完全一致**（`core/people.py`），两边各写一套过滤就会出现「工作台 5 件、日程 3 件」。会议多一条规则：`host` 是职务（「常务副市长」）不是单位，还要拿本人 `post` 比一次
- **AI 只写两句话**：一句今日重点、每条一行排序理由。模型拿到的是排好的清单，不能新增、不能改时间；出现清单外的数字整段丢弃，超过 80 字也丢弃；不可用时退回规则文案并标「按台账排序」，不假装是 AI 写的
- **不做手工新建日程**：会变成第三份时间表（台账、会议记录、私人日历），迟早对不上。也不在日程里签收/办结 —— 那等于又造一套状态机

## 消息提醒

回答一个问题：**现在该叫醒谁，为什么是现在。** 三条边界：不产生事实（每条带 `ref`，天数/进度/期次全从源数据取，不在提醒里算第二遍）、不替代日程（日程说「什么时候有什么事」，提醒说「现在叫醒谁」）、不预设通道（站内信永远可用，通道没配不等于功能没做，页面把「已送达」和「只在本机」分开写）。

| 规则 | 什么时候 | 级别 | 发给谁 |
| --- | --- | --- | --- |
| 事项已逾期 | 逾期后每天一次（不受上班时间限制） | 紧急 | 责任单位 |
| 今日到期 | 时限当天 08:30 之后 | 紧急 | 单位 + 本人 |
| 交办未签收 | 交办满 24 小时后每天 | 重要 | 责任单位 |
| 临近时限 | 到期前 3 天和 1 天各一次 | 重要 | 责任单位 |
| 进展停滞 | 停滞满 7 天后每周一 | 留意 | 责任单位 |
| 会议即将开始 | 开始前 60 分钟内 | 重要 | 本人 |
| 关注指标低于目标 | 新期次披露后 | 留意 | 本人 |
| 期次待披露 | 披露日前 2 天 | 提示 | 本人 |

规则表写在 `core/notify.py` 的 `RULES` 里，页面那张表直接读它，冒烟测试会检查每条规则都有对应的生成分支。

**去重靠 id，不靠「发过没有」**：id 是 `规则:对象:桶`，桶是日期/期次/会议 id。同一天同一件事只有一个 id；第二天桶变了自动重来（这才叫每天提醒）；跨天重置是免费的，不用另写一张发送记录表。

**外发四道闸**：只发紧急/重要（八条全推的结果是没人看，第二周就被屏蔽）、只发督办类（会议/指标/期次是给领导看的，推到单位群是噪音）、静默时段 22:00–07:00 且周末只发紧急、同批次不重发 + 日限额 20 条（定时任务 5 分钟跑一次，没有幂等就是刷屏）。批次指纹是「这批 id 的哈希」而不是条数 —— 换了一件事也是新信息。

配置复制页面「送达配置」模板存成 `config/notify.json`（已 gitignore），或用环境变量 `OCGOV_NOTIFY_*`（同名优先）。`format: wecom` 走企微群机器人 `msgtype=text`，`generic` 原样 POST 一份带 `items` 的 JSON 方便接 OA；SMTP 用标准库 `smtplib`。**配置没有 HTTP 写入口** —— 写配置的接口等于给任何能打开页面的人改推送目标的能力。

## 会议助手

管两头：**会前**一句话约会议（出草稿，确认才落库），**会后**把纪要抽成议定事项、交办进督办台账。

**会前**：`ledger` 加了 `kind`，`record`（会后记录）与 `plan`（待召开）是两个实体 —— 现有 `create()` 要求纪要原文必填、`status=draft` 指「待解析」，都是会后的事；预约的会没有原文，状态是 `planned`。但两者**放同一个文件**，因为日程和「会前 60 分钟提醒」读的都是 `list_meetings()` 的 `held_at`，进同一张表那两处一行都不用改。

**只出草稿不直接建**，两个理由还立着：① 会议没有改字段的接口，建完只能删 —— 草稿卡里那几个输入框是唯一的修改机会；② 一句话缺的信息很多，草稿卡把敞口显式列出来。`missing`（缺必填，红字，缺着不许建）与 `assumptions`（我替你定了，黄字说明理由）：只说「三点」按下午 15:00、「只说时间」按今天这个点、没说主持人按当前身份职务、「周三」而本周已过取下周三。时间解析按周一为一周起点。

参会单位按台账里真实出现过的单位匹配（现算不落盘），只做「去行政级别前缀」一种归一，**不做编辑距离** —— 猜错的单位会收到一场不属于它的会。撞车只能说「同一时间段还有另一场会」（没有人员日历，也没有会议室资源）。幂等键是 `from_message`，重复点只建一场。

**三道闸，模型不许编**（`core/meeting/extract.py`，全在服务端）：

| 闸 | 判据 | 不过时 |
| --- | --- | --- |
| 引文闸 | 每条必须给 `quote`，归一化后必须是原文的连续子串 | `quote_not_found` |
| 数字闸 | 标题/办结标准里的阿拉伯数字、时限的月与日，都必须能在原文里找到 | `number_not_in_source` / `deadline_not_grounded` |
| 白名单闸 | 责任单位只能取自实际存在过的单位 | `unknown_unit` |

引文闸是关键：模型没法靠「理解大意」蒙混。原文只写「年底前」，模型就别想给出 12-31（实测被拦，标 `deadline_missing`）。

**人工认领：校验不应该反过来卡人。** 最初版本里人工把「年底前」补成 12-20 之后，系统仍说「原文里没有 12 月」，这条永远落不了库。所以问题分两类：**硬问题**（引文对不上、字段为空、时限已过期、单位不在名单）谁改都要重新满足；**软问题**（`deadline_not_grounded` / `number_not_in_source`）本质是「疑似模型编的」，允许人工认领 —— 人改过哪个字段就豁免哪个字段，并记 `confirmed_by_human`，界面显示「人工设定 deadline」。他在这个界面上改字段，本身就是在承担责任；审计要的不是拦住人，是留得下「谁定的」。

**解析和落库是两步**：`POST /parse` 只抽取校验，`POST /commit` 才写台账。只有 `verify.status == "ok"` 的条目能勾选；混入任何一条未通过的**整体拒绝，一条都不写**（台账是有人真要去办的东西，半截写入比不写更难收拾）；`quote` 不可编辑 —— 人能改引文，等于能把校验关掉。

**会议通知只成文，不发。** `core/meeting/notice.py` 把一场 `plan` 拼成公文：标题、主送机关、时间（带星期）、地点、主持人、参会单位、议题、有关要求、落款。逐字段拼、不经模型 —— 通知错一个字就得重发，而重发的东西收件人手上会有两版。**缺字段不编**：没地点写「另行通知」、没单位写「各有关单位」，缺口同时进 `warnings` 摆给人看。导出默认写桌面（`OCGOV_EXPORT_DIR` 可改），UTF-8 带 BOM（记事本不乱码），同名不覆盖而是加 `-2`，页面上改过的正文优先于系统原稿。**这里没有「已送达」这个概念** —— 系统不知道谁收到了，所以界面只说「复制后由你发」；发送与撤回见下一步第 4 条。

## 督办闭环

```
待签收 ──签收──► 办理中 ──提交办结──► 待审核 ──确认办结──► 已办结
                    ▲                     │
                    └────────退回─────────┘
催办：待签收 / 办理中 / 待审核 都可以，但不改状态
```

守卫集中在 `_guard()`：**状态不对一律拒绝**（不能跳步、不能重复）；**提交办结三件套**（至少一条进展记录 + 办结说明 + 佐证材料，缺哪样报哪样）；**退回必须写理由**；**催办不算进展**（`last_activity` 排除催办，否则天天催办的事项永远不会被判定停滞 —— 等于用催办把问题刷绿）。

被拒的请求返回 `ok=false` + 中文原因且**不落任何数据**。前端不预判能不能点，按钮按 `allowed_actions` 渲染 —— 两套规则一定会漂移，只留一套。

会议那边允许人工豁免软校验，督办这里**没有**：会议事项是从自然语言里猜出来的，猜错了该让人修；督办流转是人对系统的正式表态，签收了就是签收了，不能有「改一下让它通过」的路径。

**批量催办不原子**（与会议落库相反）：催办只是往事件流记一条提醒，部分成功没有副作用，硬要原子性只会让能催的也催不出去。返回里 `urged` 与 `failed` 分开列并带原因。

**并发**：`advance()` 和 `create_item()` 整段包了模块级 `RLock`（内部还会调 `get()` / `assess()`，所以可重入）。这只解决单进程内的并发，多 worker 共享 `data/*.json` 仍会互相覆盖。

台账三个入口：罗盘底部预警条「进入统筹推进」（唯一常驻总入口，逾期数角标挂条标题上）、预警条里单条事项直接定位、会议助手里已落库事项的台账编号跳转并带返回。顶栏原「统筹推进」按钮已撤 —— 两个入口指向同一个台账，反而让人以为是两套东西。

## 权限与身份

一句话：**读靠 session（有就用，没有按演示全量），写靠 session + 三档角色 + 行级责任单位，没登录一律拒绝。** 设计与取舍见 `docs/permission-design.md`。

| 角色 | 对应 | 看什么 |
| --- | --- | --- |
| `leader` | 市领导 | 全市（不按单位过滤） |
| `dept-leader` | 分管领导 | 分管的那几个局 |
| `bureau` | 委办局 | 本单位 |

`leader ⊃ dept-leader ⊃ bureau`，父角色自动拥有子角色的全部权限。**未知身份一律回落到 `bureau`**（最窄那档），绝不出现「查不到人所以放行」。「是不是全市」只看角色，不看 `units` 空不空 —— 早先按空 `units` 推是个隐式约定，新建身份忘填单位就等于悄悄把全市数据给了他，而且不报错。

**判定只在一个地方**：`authz.can(scope, action, resource)`。动作名统一「域.动词」（`oversight.sign` / `meeting.commit`），**授权和审计共用同一套词表**。默认拒绝；行级锚点是责任单位（主办 ∪ 协办）；写比读更紧（协办不能替主办签收，确认办结和催办另算一档）。

**一张表管住全部写接口**。`app/main.py` 顶部的 `WRITE_POLICY` 用 `(方法, 路径正则, 动作)` 登记每个写路由，`do_POST/PATCH/DELETE` 在路由之前各查一次表：

| 第三列 | 含义 | 覆盖 |
| --- | --- | --- |
| `None` | 演示态放行，不登录也能用 | 问数 / 停轮次、会话增删改、个人工作台、收藏、提醒已读、日程简报、材料装配、文件解析、登录登出 |
| `GATE_SESSION` | 要登录，行级由业务层再判 | 督办建档 / 流转 / 催办（闸门看不到 `units`，handler 用 `_require` 再判） |
| 具体动作名 | 交给 `authz.can()` | 模型配置 / 专家名单 / 插件开关 / 提醒群发 / 会议删改 = 市领导；上传文档建库/上传/删除 = 登录即可 |

**表外一律 403**（`write_unregistered`）。这条比「记得加 `_require`」重要得多：新加接口忘了登记，得到的是「被拒」而不是「匿名可调」。`smoke.py::test_write_policy` 扫路由字面量，漏登记直接红灯（这条断言本身做过变异验证）。

配置类锁市领导而不是「登录就行」：provider 里存着 `api_key`，能改它的人就能把所有人的提问导到自己服务器上；`/api/notify/dispatch` 同理，它是往外发消息的动作。演示态留匿名口子是产品核心路径（双击 → 打开就问），**代价要认**：未登录时身份来自 `X-Person-Id`，可以冒充。

**口令与 session**：没有内置默认口令（仓库公开，写死的默认口令等于没口令）。三条来源按优先级：`OCGOV_PASSWORD` 环境变量 → `data/credentials.json` → 首次启动随机生成并只在控制台打印一次。落盘只存 `pbkdf2_hmac` + 盐；**没有任何记录 = 未初始化 = 一律拒绝**（曾经的坑：`verify()` 会「没记录就顺手用当前口令补建」，等于谁先登录谁定口令）。session 用 `secrets` 签发，TTL 8 小时，登出即吊销；登录失败不区分「没这个身份」和「口令错」。

**读收窄是渐进的**：只有督办台账和知识库按 session 收窄，指标/会议/日程/提醒仍是全量 —— 未登录的演示浏览不能因为上了权限就一片空白。登录后 `_person()` 的优先级是 `session > X-Person-Id > 默认`，副作用是测试里不能给所有请求全局挂 session，否则「换身份看不同数据」的用例会被压成市长视角，变成假通过。

**审计**：`data/audit.jsonl`，append-only，五字段 `ts / actor / action / target / payload`。写操作全记（**包括被拒绝的**，不记就看不到越权尝试），正常读不记，越权动作名固定 `access.denied`。审计是旁路：写不进盘也不能让一次合法的写失败，所以异常被吞掉。没有查询接口，读它用 `audit.tail()`。

## 判定规则

| 板块 | 判定 | 依据 |
| --- | --- | --- |
| 经济运行 | 8.9% ≥ 目标 6.5% → 正常 | 当月增速对比年度目标 |
| 招商引资 | 完成率 71% ≥ 70% → 正常 | 项目数 / 年度目标 121 个 |
| 重大项目 | 73.9% < 时序 75% → **预警** | 累计完成率对比 1—9 月时序进度 |
| 社会治理 | 96.2% ≥ 95% → 正常 | 市级考核基准线 |
| 民生保障 | 84% ≥ 80% → 正常 | 已验收项数 / 年度 45 项 |

阈值全是 `workbench.py` 里的显式常量，没有「AI 觉得正常」。

## 接真实数据要改哪里

**① 有真实大数，只要当期值对得上** → 加进 `core/metrics/realdata.py` 的 `REAL_ANNUAL`。一条记录带 `value` / `yoy` / `period` / `source`（口径、发布单位、披露时间三件套一个都不能少），`query_metric()` 自动覆盖当期值，上层全不用动。

**② 要真正调部门接口取数** → 把 `realdata.real_annual_value()` 换成「调接口」，取值、口径、出处、时效的判定都不动。它返回的结构本来就是 `query_metric()` 认的形状。

`mockdata.py` 的 `_VALUES` / `_BREAKDOWNS` 是没有真实值时的底座（也提供 24 个月走势），只在要连演示值一起替换时才动。

三条硬约束：接口没返回的字段，不许前端补、不许模型补；`published_at` 与 `period` 必须来自接口，不能按「次月 10 日」推算（真实披露会延期）；**取数失败要显式报错，不要静默返回上一期** —— 静默兜底是政务数据事故的常见源头。
