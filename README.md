# oc-gov · AI 市长工作台

> ⚠️ **开发中**：功能与接口仍在变动，暂不建议用于生产环境。
> 演示数据均为模拟数据，未接入任何真实政务系统。

一屏把「问一句」和「看全局」放在一起：左边自然语言问数，右边全市罗盘 + 五块板块看板，底部跑督办预警条。**每个数字都能点开查口径、责任部门、报表和披露日期。**

从 `octop/octop-dashan/prototype/` 的三个原型收敛成一个独立项目，不再依赖 Octop 平台运行。

## 快速开始

```bat
run.cmd              :: http://127.0.0.1:8090
run.cmd 8091         :: 换端口
```

- 零第三方依赖，标准库即可跑（Python 3.11+）
- 跨会话记忆是**可选增强**：装了 `octop-memory`（`pip install octop-memory`）才启用，会记住领导长期关注的指标/维度/主题，开新会话时作为背景喂给模型；不装则静默降级，其余功能不受影响
- 模型：点右上角模型胶囊配置（或访问 `/#models`），支持多服务商多模型、一键测连通性。**不配也能跑**：问数退回规则解析，罗盘和预警不受影响
- 首次启动从 `config/local.env` 自动导入一条 provider；没有该文件就从空配置开始，在页面里加
- 首次启动自动生成 8 条示例督办台账到 `data/oversight-state.json`；删掉该文件重启即回到基线

**想直接看到会议与问数的完整效果**，跑一次演示数据脚本：

```bat
python seed_demo.py            :: 写入 3 场演示会议，知识库 19 → 26 条
python seed_demo.py --force    :: 清掉重建；不加参数时已有演示数据会跳过
python seed_demo.py --dry-run  :: 只打印将要做什么，不落盘
```

`data/` 不进版本库（里面会有会话和模型配置），所以刚 clone 下来会议库是空的 —— 指标口径 11 条、督办台账 8 条都是代码内置的，只有会议记录依赖 `data/meetings.json`。不跑这个脚本，问「上次开会定了什么」会答「没有相关记录」，那不是坏了，是还没数据。演示数据带 `source="demo"` 标记，与 `people.py` 里演示市长的 `demo: True` 是同一套语义。

## 这个页面证明了什么

- **能同时容纳「问一句」和「看全局」**，且问数和罗盘用同一套指标字典 —— 问「规上工业增速」和看那张卡片，数字必须一致，不会出现「页面写 8.9、助手说 8.5」
- **每个数字都可溯源**：点卡片 → 右侧抽屉给出数值、同比、走势、口径定义、责任部门、报表名、披露日期、接口地址、使用注意
- **底部预警不是写死的文案**，来自督办台账实时扫描（逾期 / 今日到期 / 临期 / 签收超时 / 停滞）
- **模型不碰数字**：模型只输出「问的是哪个指标、哪一期、怎么拆」的查询计划，数值由接口返回后原样拼装。模型说错话最多答非所问，不会造成错数
- **多轮能用指代**：「那上个月呢」「换成区县看」这类追问不用重复指标名，回灌的历史里也不含数值，模型没有复述数字的机会
- **模型可换**：多服务商多模型随时切换，带连通性测试（真发 ping 而不是只列模型），换服务商不改代码
- **督办能写闭环**：预警条上每一条都能点开，签收 / 反馈进展 / 提交办结 / 确认办结 / 退回 / 催办全部走状态机守卫，被拒绝的操作不落任何数据。状态、天数、风险等级都由代码算，催办文案由 `assess()` 的判定理由拼出来，模型没有参与
- **日程不产生新事实**：AI 日程里每一条都能点回台账或会议记录，模型只写一句重点和一两条理由，出现清单外的数字整段丢弃，模型不可用时退回规则排序并如实标注
- **材料是装配出来的，不是写出来的**：材料助手的骨架、分段、每处数字和出处都由代码拼装，页脚列出每个数字来自哪个部门哪份报表哪天披露；模型只写「下一步」一节，且只能用材料里的数字。可复制 Markdown、下载、打印
- **上传的材料不会冒充答案**：材料只影响「问的是哪个指标、哪一期」，数值仍由接口给；材料里的数真要露出来，就和库值并排、各自带出处，核不上原文就整块不显示（见「参考材料」的 A / B 两档）
- **知识库检索的是原文，不是模型复述**：「上次开会定了什么」「环保局那件事办到哪了」这类问句在指标字典里匹配不到，以前会被当成"没注册的指标"拒答。现在由代码检索已有记录（指标口径 / 督办事项 / 会议议定），返回的是**逐字原文和出处**，每条都能点回台账或会议记录。模型不参与检索，也就没有转述的机会
- **提醒只搬运，不制造**：消息提醒从台账状态、会议时间、指标披露里派生，每条都能点回出处；同一件事每天只提醒一次，第二天没办会再出现；只有「紧急」「重要」两档会外发，其余留在面板里。站内信和浏览器桌面通知开箱可用，企微群机器人 / SMTP 邮件填了配置就能送出去 —— **不配也能用**，页面上把「送到没有」分开写

## 这个页面**没**证明什么

写汇报材料前务必看这一节。

1. **没有真实数据**。11 个指标的数值全部是构造的。证明的是「链路能通」，不是「数据可信」
2. **没有权限**。谁打开都能看全部数字和预警。真实场景「市长看全局、副市长看分管、委办局只看自己」是硬约束，这层完全没接。**个人工作台那个身份切换是演示用的**：它只决定「看谁的关注列表、我跟进哪些单位的事项」，不拦任何数据，也拦不住任何人——别把它当成三档权限。**分管单位是写死在 `core/people.py` 里的演示映射**，不是从组织架构/干部系统同步来的；真实部署里这层要换成人事主数据，派生逻辑（`follow_items()`）不用动
3. **没有指标中台**。真实系统的指标注册、口径变更、同源同口径校验是另一套工程，这里假设那张字典表已经存在
4. **民情焦点是假的**。三条固定条目，真实系统要接 12345 工单聚类
5. **顶部工具现在都能点开，但「叫醒」的范围止于本机**。会议助手、AI 日程、材料助手、消息提醒四个顶栏入口都能用；统筹推进不在顶栏，从罗盘底部预警条进。提醒有规则表、有跨天去重、有站内信和浏览器桌面通知，外发通道（企微群机器人 / SMTP）的代码也写完了 —— 但**默认一个通道都没配**，所以责任单位收不到。这不是没做，是没填凭证：页面「送达配置」里能看到当前状态、复制配置模板、发测试消息
6. **督办能写，但没有「鉴权」也没有「送达回执」**。签收 / 办结 / 退回能操作、能留痕，提醒也能外发。但三件事没解决：谁打开面板谁就能替任何单位签收（`actor` 是前端传的字符串，不是登录态）；企微机器人只管发、不回执，**发出去有没有人看系统不知道**；也没有按单位路由，一个 webhook 对应一个群，全市的提醒进同一个群。所以对外发送的按钮不做 `force` —— 无鉴权的强制群发等于把群交给任何人
7. **知识库（指标/事项/会议）不含政策文件，但另有「资料库」专门收上传文档**。前者只收系统自己产出的三类记录；后者在设置 →「资料库」里上传任意文件（md/txt/csv/tsv/json/html/docx/xlsx），切成片段建索引，问句来了召回相关原文。检索到的永远是原文、带出处，模型不转述数字 —— 向量化是可选的（装了 `fastembed` 走本地 ONNX 语义检索，没装自动退回 bigram 关键词检索）
8. **没有响应式**。最小宽度按 1180 设计，更窄会出现横向滚动
9. **约会议只能建，不能改、不能通知、不知道谁来**。对话里能把一句话变成一场会，草稿卡上是「我替你推定了什么」，但：没有人员日历也没有会议室资源，撞车只能提示「同一时间段还有另一场会」，查不了「张局长那个点有没有空」；建完之后**没有改的接口**，只能删了重建；也不发会议通知——约好的会只进日程和会前 60 分钟提醒，责任单位并不会因此收到消息
10. **存储只支持单进程**。`data/*.json` 的写锁是进程内的，`ThreadingHTTPServer` 多线程没问题，但用 `gunicorn`/多 worker 起两份就会互相覆盖。要多进程或多人用，得换 SQLite/PostgreSQL（`core/store.py` 是唯一需要改的地方）
11. **材料得先有人转成文本**。`.xlsx` / `.docx` 能读了，但 PDF / 图片 / 扫描件一概不收，`.xls` / `.doc` 也读不了（旧版二进制）—— 得先另存成新格式。另外材料**只在当轮生效**：正文不落盘、不进知识库、下一轮不再带进 prompt（会话里只留文件名和字数，用来回答「刚才参考了哪份」）。Word 里的图片读不出来，文档只报「N 张图片没有读入」

依赖方向是单向的，不要反向引用：

```
app/main.py ──► app/workbench.py ──► core/metrics ─┐
      │                └─► core/oversight ┘
      ├──► core/modelcfg ──► core/store
      ├──► core/chat    ──► core/store

```

`core/` 不感知 HTTP，也不感知页面；`app/` 只做聚合和转发。`modelcfg` 与 `chat` 互不依赖（删除 provider 后要清理会话里的悬空引用时，由 `app` 层调 `chat.clear_model_refs`，不让两个 core 模块互相 import）。

`core/meeting/*` 和 `core/oversight/*` 里的业务函数全部不依赖 HTTP、不读全局请求上下文，**这是为后面包成 MCP 工具留的**：`extract()` / `verify_item()` / `ledger.commit()` / `oversight.advance()` / `oversight.scan()` 直接拿去当 tool handler 就行。

## 模型配置

支持**任意 OpenAI 兼容服务**，可配多个 provider、每个挂多个模型。

- 模型标识统一是 `"provider_name/model_id"` 字符串（`deepseek/deepseek-chat`），界面选项、会话粘性、全局默认、接口入参全用这一个标识
- 三层回退：**会话里的 model_ref → 全局 active_model → config/local.env**
- **显式指定了不存在的模型不会静默替换**，而是在 `resolve()` 返回里标 `fell_back=True`，让上层能提示「你要的模型没配好，已用默认」
- 删 provider 或改模型列表后，`active_model` 和会话里的 `model_ref` 会被自动清理，不会留下一个点开就报错的悬空引用
- 只改备注、不传 `api_key` 时，已有密钥保持不变（不会被顺手清空）
- 连通性测试是**真发一条 `ping` 请求**（`max_tokens=1`，30s 超时），不是只列模型 —— 「地址填对了但模型下线」是最常见的一类故障
- 密钥明文存 `data/models.json`（与 octop 一致，单机自托管没有 KMS 可用），该目录已 gitignore。**列表接口默认只返回掩码**，只有真正调模型时才取明文

页面右上角的模型胶囊点开就是配置面板；也可以直接访问 `http://127.0.0.1:8090/#models`。

首次启动时，如果 `data/models.json` 不存在，会从 `config/local.env` 自动导入一条 provider —— 老部署升级上来不用重配。**不配置也能跑**：问数退回规则解析，罗盘和预警不受影响。

## 对话机制

- **会话**（thread）存 `data/chats.json`，消息按 `seq` 单调递增追加，一轮结束一次性落库（流式过程中不写盘）
- **多轮指代**靠回灌最近 4 轮对话，不做 query 改写：「那上个月呢」能正确解析成上一轮的指标 + 上一个月
- **回灌给模型的历史不带数值**。assistant 消息只回灌「上一轮问了哪几个指标、什么意图」，一句 `具体数值见界面，不在此重复`。原因是本项目的安全边界：模型一旦在上下文里看见 `8.9%`，下一轮就更可能复述甚至改动它。给人看的 headline 完整存在消息里，只在界面渲染
- **流式用 SSE**（`POST /api/ask/stream`），推的是**真实阶段**：`start`（会话已接入）→ `plan`（意图与指标已解析，来自模型的真实输出）→ `done`（完整结果）。**不是**把答案按字切开的假打字机 —— 模型只输出结构化查询计划，本来就没有可读的正文流，做成打字机效果等于骗人
- 会话粘性：新会话创建时钉住当前默认模型，之后改全局默认不会把老会话悄悄换掉
- **能写的那一类问句单独前置**。「约个会」既不是问数也不是查记录，它要写。这类问句在指标字典里一定匹配不到，不前置就会变成「没有对应的指标」——用户提了个能办的需求，系统回一句它办不了。所以 `meetplan.wants()` 的判断放在**模型规划之前**：既省一次调用，也不会让模型把「约会议」判成取值或依据（见「会议助手 · 会前」）

### 这一轮到底带了什么进去

答案底部一行小字：`3 次模型调用 · 1.2s · 上下文 8/12 轮 · 参考 2 个附件`。

以前这块只有调用次数和耗时，上下文是纯黑盒。问到第十几轮，模型突然接不上「那上个月呢」，用户唯一的解释是「这系统不太行」——真实原因是 600 token / 10 轮的预算只够带最近几轮，更早的被裁掉了。

现在裁了就写出来，并且标橙：`上下文 10/14 轮 · 前 4 轮已裁掉`。悬停给出完整解释（带走几轮、裁掉几轮、占了多少 token），用户就能自己决定是「把主体讲清楚」还是「开个新会话」，而不是反复重问同一句话。这个数由 `core/chat.context(out=...)` 回传，不是前端估的。

附件同理：只写「参考 2 个附件」，名字在悬停里。传了三份文件，事后得说得清是哪一份起了作用 —— 不然「参考了附件」等于没说。

### 导出与查找

每轮答案右上角有「复制」和「导出」。复制解决「贴到别处」，导出解决「发给别人 / 存档」—— 政务场景里后者更常见：一份带出处和口径的答复要跟着流程走。

导出的是 Markdown，内容不是屏幕上那些字的截图转文字，而是重新拼的：问题、结论、指标表（含责任部门 / 报表 / 披露日）、依据、专家解读、材料对照、这一轮的可信度脚注。文件名取问句前 30 字，接日期。

**历史会话里点导出同样能出。** 早期版本只从 `__r`（刚跑完的原始结果）取数据，历史消息上挂的是 `__m`，两者结构不同 —— 结果就是历史导出一直是空的。现在统一走 `historyView()` 映射，两条路径共用一份构造逻辑。

**会话内查找**：`Ctrl+F` 或气泡区右上角的放大镜，搜的是**当前会话的气泡**（会话列表那个搜索是另一件事）。长了二三十轮的会话里回头找「上次那个 8.9% 是哪一轮说的」，靠滚轮已经不现实。

它只滚动 + 临时描边 1.6 秒，**不改写文本节点**。做 `<mark>` 高亮要拆开文本重新拼 DOM，而复制、折叠、收藏星标、口径胶囊的事件绑定全挂在那棵树上，弄坏一个就多一个静默 bug —— 用户要的只是「跳过去看一眼」。

### 切会话不打断正在跑的那一轮

以前一边提问一边点开历史对话，答案回来时会画到「当前显示的会话」里：于是它出现在错误的会话里，切回去又没了。

现在的做法不是禁止切换，而是给容器挂 `turnId`：返回时只写进「这就是它的那个容器」；容器已经不在文档里，就只落库、不渲染，切回去时从消息记录里补上。**不禁止切换是有意的** —— 一轮可能要跑十几秒，这时候想顺手翻翻上一条会，是很正常的动作。

### 左栏：会话列表与收起

会话切换原来是一个 `<select>`（「新会话 / 标题 · 条数」），标题一长就被截成省略号，也看不出最后说了什么。现在按聊天客户端的做法换成两屏（参考 WorkBuddy 的侧栏）：

| 位置 | 内容 |
|---|---|
| 标题行左上角（`#askFold`） | 收起侧栏 —— 和 WorkBuddy 一样把开合放在左上角 |
| 标题行右上角 ☰（`#askChats`） | 切到「历史对话」屏，`#chats` 也能直达 |
| 历史屏标题行 | 「历史对话 · N」+ ✕ 回对话 |
| 历史屏列表第一行 | ⊕「新对话」—— 和会话条目同一列、同宽，不挤在标题行里（WorkBuddy 的「新建任务」就这么排） |
| 会话条目 | 标题 + 最后一句预览 + 条数，按天分组，当前那条高亮；点一行就切过去并回到对话 |
| 历史屏页脚 / 对话底部 | 当前模型（`deepseek-chat`），两处是同一份状态，都点得开设置 |
| 收起后 | 整块缩成 54px 竖条（竖排「智能问政」+ 在线点），城市罗盘自动补满宽度 |

收起用的是「除窄条外全隐藏」（`html.ask-fold .ask > *:not(.ask-rail)`）。早先那版逐个点名 `.ask-head`/`.ask-body`/`.ask-chats`，特异性低于 `.ask.show-chats .ask-chats` —— 开着历史屏再点收起，历史屏会留在 54px 里，右侧还挤出半个「新对话」按钮。这类优先级打架只会在「先点 A 再点 B」时出现，截图截单个状态看不出来，已写成 smoke 静态断言。

收起状态记在 `localStorage.ocgov.askfold`，由 `<head>` 里的内联脚本在首屏前应用 —— 否则每次打开都会先铺开再缩回去闪一下。会话数据只有一份 `THREADS`（`/api/threads`），设置里的「会话记录 N 个」和左侧列表都读它，不再有第二个计数来源。

## 参谋团（专家解读）

输入框上方一个下拉：经济参谋 / 民生参谋 / 生态环境参谋，单选；最后一项「参谋团」一次叫上全组。选中后答案下方多出对应的解读卡片。**不选人时这一行是空的**——没有「不召唤」这个选项，空就代表没人插话；要取消，再点一次已选中的那位。

同一个名单还有第二个入口：**输入框里打 `/`**（中文输入法上屏的 `／` 也认）就地弹出这层菜单，接着打字是过滤（`/经` 只剩经济参谋，`/eco` 按 id 也能命中），上下键选、Enter 确认、Esc 连斜杠一起清掉。两条入口**同源同出口**——菜单项来自同一个 `/api/experts`，选中也走同一个 `selectExpert()`，所以不可能出现「下拉是 A、斜杠是 B」的两种状态。

三个只有真做的时候才会暴露的约束：

- **只在行首认**。`投资/工业`、`环比/同比` 是问句里的正常写法，判定要是「含 `/`」就弹菜单，问题根本打不完。所以判的是 `value[0]`，不是 `indexOf`。
- **全角 `／` 必须认**。中文输入法按 `/` 上屏的常常是 U+FF0F，只认半角等于让一半用户打不出来。
- **组词中的 Enter 不抢**。中文选词也是 Enter（`e.isComposing` / keyCode 229），抢了就是一打中文就误选人。

**`/` 里只放参谋，不放顶栏的会议助手 / 督办 / 日程 / 材料 / 提醒。** 那些是页面级导航，塞进来会让人以为能在对话里指挥它们，实际只是弹个面板。要扩成一个真正的指令集（`/会议` 直接建会、`/督办` 直接派单），得先给每条指令定义「说什么就做什么」，不能只是换个方式开弹窗。

**专家不取数。** 数值、口径、出处仍由 `core/metrics/ask.py` 走指标接口拼出来，专家只在这之后补一段「怎么看」。若让专家自己查数，同一场会里经济参谋说 8.9%、民生参谋说 9.1%，谁也说不清该信谁 —— 数字只能有一个来源。

**数字闸**：解读里出现阿拉伯数字或百分号，**整段丢弃**并注明原因，不做「修正」。唯一例外是指标名自带的数字（如「12345 群众诉求按期办结率」），校验前先剔掉那几个片段，免得冤枉。判定是纯函数 `_has_forbidden_number()`，可单独断言，不靠提示词自觉。

传给专家的输入也不含数字：只有指标名称和**方向信号**（「同比上升」「环比下降」，由代码从原始值折算）。专家想报数也没有素材。

**不做合并总结**：召唤三位 = 同一个问题、同一组数字、三段不同角度的看法，各自独立。合并必须再调一次模型，那次调用不产生新信息，只多一次编数字的机会。

模型没配好时不让整条问答失败：专家段标注「未配置模型」，数值答案照常返回。

## 参考材料（附件）

输入框左侧的回形针选文件 → 浏览器里读成文本 → 跟着这一轮的问题一起交给 **planner**。文件内容**不进答案，只进「查询计划」那一段**：模型看得到材料，用它判断「用户问的是哪个指标、哪一期」；数值仍然只来自指标接口。

也只交给 planner，**不进专家团**。专家的输入本来就不含数字，只给指标名和方向信号；这里要是顺手把材料塞过去，等于给专家开了一条报数的路。

支持两类：

- **纯文本**：`txt / md / csv / tsv / json / log / yaml / xml`，浏览器里直接读（UTF-8 猜不准会自动换 GBK）
- **`.xlsx` / `.docx`**：浏览器把字节 `POST` 给 `/api/attachments/parse`，服务端解析成文本再回来，之后走同一条通道

Office 文件为什么不在浏览器里解：它们都是 zip + XML，前端要写一遍解压和格式还原，服务端再写一遍，两份实现迟早在某张表上分叉 —— 而且是「一边读出 7.2%、另一边读出 0.072」这种最难发现的分叉。解析只留一份，在 `core/docparse.py`，**标准库实现，不引 openpyxl / python-docx**。

PDF、`.xls` / `.doc`（旧版二进制）、PPT、图片仍然**明确拒绝并说明原因**（「PDF 要解析库」「旧版 Word（.doc）请另存为 .docx」），不静默丢弃 —— 收下一个读不出内容的 PDF，比当场拒绝更糟：用户会以为系统看过了。格式判断看的是**包里的部件**不是扩展名，所以把 xlsx 改名成 .docx 也照样认得出来。

三个额度，前端截一遍、后端再截一遍：

| 限制 | 值 | 为什么 |
| --- | --- | --- |
| 份数 | 5 | 再多就不是「参考一份材料」，是把整台电脑倒进来 |
| 单份字数 | 12000 | 一份月度报表正文的量级 |
| 合计字数 | 30000 | 超过这个数，材料会把问题和指标目录一起挤出 prompt |

后端**必须再截一次**：`/api/ask/stream` 是公开接口，curl 直接塞 200MB 字符串进来，前端那层挡不住。

**编码是这里最容易踩的坑。** 政务文件的 csv、txt 十有八九不是 UTF-8（Excel 导出默认 GBK）。直接 `readAsText` 会读出满屏 `\ufffd`，用户只会觉得「这功能坏了」。所以按 `ArrayBuffer` 读，先猜 UTF-8，替换字符超过千分之二就换 GBK 重解，取坏得更少的那个。

**材料落库只存清单，不存正文。** 一份一万多字的材料如果跟着每轮上下文回灌，几十轮之后光历史就能把 600 token 的预算吃干净 —— 后面几轮模型连问题本身都看不全。

### 读 Excel 时真正难的那一步

不是解压，是**「存的」和「看到的」不是一回事**：

| 在 Excel 里看到 | 单元格里实际存的 |
| --- | --- |
| `7.2%` | `0.072` + 一个「0.00%」数字格式 |
| `2026-09-30` | 序列号 `46295` |
| `1,234.5` | `1234.5` |

直接把 `<v>` 读出来喂给模型，模型看到的是「46295」。更要命的是材料对照的原文闸按 token 精确匹配：材料里写 `7.2`，我们手上是 `0.072`，闸判「材料里没有这个数」，对照块**静默不出现** —— 功能看着没坏，其实坏了，而且一句报错都没有。

所以解析器做的是**按数字格式还原显示值**，不是取原始值。另外 1900 系统有一处补丁：微软为了兼容 Lotus 保留了不存在的 1900-02-29，序列号 ≥ 60 要整体减一天，少了这一步 2026 年的日期会全部差一天。

还有两处会让人误判的地方：

- **合并单元格**只保留左上角的值，其余格是空的。把标题复制到整行看着更整齐，但会让模型以为有四个不同的指标 —— 所以只留一个，并在芯片悬停里说明有几处合并
- **公式格可能没有缓存值**。文件如果是程序生成的、没在 Excel 里存过，`<v>` 就不存在，读出来是空。这种情况会在提示里点明「N 个公式格没有计算结果」，不然用户以为那一行本来就是空的

### 读 Word 时真正难的那一步

不是抽文字，是**判断哪些节点算「正文」**。`word/document.xml` 里同时住着：

| 节点 | 它在文件里 | 人看到的 | 读进来会怎样 |
| --- | --- | --- | --- |
| `w:del`（修订删除） | 旧字还在，为了能「拒绝修订」 | 看不见 | 把删掉的旧数字当现行数字 |
| `w:vanish`（隐藏文字） | 字在，只是设为隐藏 | 看不见 | 把「内部口径，不要外发」那段喂给模型 |
| `w:instrText`（域代码） | `PAGE` / `MERGEFORMAT` 这类指令 | 只看到域的结果 | 正文里冒出英文指令串 |

这三种都不报错、不警告，只会让材料「看起来对、其实不是原文」。而材料对照的原文闸恰好是拿这些 token 去核的 —— 多出一个 `7.25`，对照块就会拿一个用户根本没看见的数去做比对。

所以解析器只走「人会看到的那条路」：跳过 `w:del`、跳过带 `w:vanish` 的 run（并在提示里报「跳过 N 处隐藏文字」）、只认 `w:t` 不认 `w:instrText`。表格按 TSV 一行一行给，行列位置保留：横向合并（`gridSpan`）补足空格、纵向合并（`vMerge`）的续格留空 —— 不补的话整张表会左移一格，而政务报表的表头十有八九是合并的。标题层级从 `styles.xml` 的 `outlineLvl` 取（段落上没有这个信息），输出成 `#` 前缀。

图片读不了，只统计张数并写进提示。整份都是图片的文档会明确回「只有 N 张图片，图片要 OCR，本机没有」，而不是笼统的「没有文字」—— 前者告诉用户该去截图，后者只让人困惑。

夹具 `tests/fixtures/sample.docx` 是**真 Word 存的**，`tests/fixtures/make_samples.ps1` 是生成脚本（需要本机装 Office）。手搓 XML 只能证明「解析器认我自己写的东西」，证明不了「认得 Office 的输出」；反过来，修订、域代码这些又没法靠打字造出来，所以那几条在 `tests/smoke.py` 里用最小 XML 合成。

### 材料里的数字：A / B 两档

这是接附件之前必须先定的一件事：材料上写着「7.2%」，库里是「5.6%」，怎么办？

**A 档（已上锁）：材料里的数字不进答案。** 不进 headline、不进 facts、不进专家解读。理由是这个项目的底线是「每个数字都能点到出处」—— 一旦 headline 里出现一个来自上传文件的数，那句话就再也核不了了：文件在用户电脑上，服务端只有一份截断后的临时文本，不留存。

**B 档（已落地）：并列，不合并。** 检测到材料里有本轮指标的数值时，答案下方多一块对照：

```
材料      7.2%    摘自《9月统计月报.csv》：规上工业增加值同比增长 7.2%
指标库    5.6%    市统计局《本市统计月报》，2026-09
```

两个数各自带出处并排放，用户自己判断差在哪（通常是「累计」和「当月」的区别），而不是系统替他选一个。

配得上才显示，四道闸：

| 闸 | 判据 | 不过时 |
| --- | --- | --- |
| 指标闸 | `metric_code` 必须在指标字典里 | 静默丢弃 |
| 原文闸 | 数值必须在材料原文里**逐字符命中**：`7.2` 不算命中 `7.25`，`7.20` 视同 `7.2` | 静默丢弃 |
| 意图闸 | 只在单指标取值 / 走势场景配对，多指标对比不配 | 整块不出现 |
| 同指标闸 | 材料说的必须是本轮主指标 | 那一行不出现 |

**原文闸是这块能不能成立的关键。** 模型编一个「材料值」，界面就会显示成「材料写的是 7.2，库里是 5.6」—— 用户以为系统替他核对过，其实那个 7.2 是模型编的。所以宁可少显示，也不显示一个没在原文里出现过的数。

**配不上就不显示，因为错配比不显示更糟。** 材料里那个 7.2% 若是「1—9 月累计」，库里 5.6% 是「9 月当月」，两个数都对，硬摆成「对不上」会让人以为数据错了。

### 明确没做

- **PDF 解析**。要引解析库，破零依赖；而且 PDF 是排版格式不是数据格式，取出来的数字经常错行错列 —— 真要接，它读出的内容也不该进材料对照
- **PPT 解析**。技术上同一套（zip + XML），但 PPT 是给人看的版面不是数据，读出来的文本框顺序通常不是阅读顺序
- **`.xls` / `.doc`（Office 97-2003）**。那是 OLE2 二进制，和 xlsx / docx 毫无关系，标准库做不了。加了密码的新版文件也是 OLE2 容器，同一个报错，提示另存为并去掉密码
- **Word 里的图片和文本框**。图片要 OCR，本机没有；文档型只报「N 张图片没有读入」
- **OCR**。本机没有，也不该在单机演示里假装有
- **让材料提供数值**。材料只影响「问的是哪个指标」，不提供数值。这条不松，A 档才有意义
- **材料进知识库**。上传只在当轮临时生效，不落盘、不进检索。要长期可用的文档，走设置 →「资料库」单独上传（那才是入库建索引的地方，见下方「资料库」一节）

## 个人工作台

顶部两个板块并排：**城市罗盘**（全市视角）和**个人工作台**（我的视角），切换不换路由，`/#desk` 可直达。工作台从上到下三块：**我的关注 → 关注动态 → 重点注意事项**。

**每个人一份关注列表。** 关注指标可以自己加、自己删（标题行右侧「管理关注」，或卡片末尾的虚线「＋ 添加关注」），按身份存在 `data/workspaces.json`：

```
{"people": {"mayor": {"watch": ["GDP_TOTAL", ...], "seen": ["metric:...:a1b2c3d4"], "updated_at": "..."}}}
```

- 没改过的人读默认值（`core/people.py` 的 `DEFAULT_WATCH`），**只读不写盘** —— 否则一个 GET 也会生成文件，让人误以为"这人配过"
- 全量替换（`POST /api/workspace/watch` 传完整 `codes`）而不是 add/remove：幂等，连点两次不会加两遍
- 校验在 `core/people.set_watch()`：未注册指标直接拒、重复项去重保序、上限 8 个（现有指标 11 个，全关注等于把罗盘搬过来）
- 写关注与写已读都落在同一个人身上，所以 `set_watch` 是**合并**写、不是覆盖 —— 否则改一次关注就把已读记录抹掉了

**身份是演示的，不是登录态。** 右上角可切「市长 / 常务副市长 / 市生态环境局局长」，三个身份的默认关注刻意不同，切换能看出确实换了人。请求用 `X-Person-Id` 头标识，后端只认白名单里的三个 id，未知 id 回落市长。**页面和 `/api/people` 都写明 `demo: true`** —— 别把这个当成权限。

**我的关注**卡片走的是 `kpis(codes)`，和罗盘 KPI **同一条取数路径**，所以同样能点开抽屉看口径、责任部门、报表名、披露日期 —— 不存在「工作台单独算一套数」。

**收藏问答。** 每条 AI 回答右上角一个星号，点亮就把这一条钉进「我的关注」（和指标卡同一个网格里的卡片，`core/saved.py`），再点一次取消。几个刻意的决定：

- **收藏的是那一条消息，不是「这个问题」。** `id` 就是 message_id，点开回到原会话原位并闪一下。只存一段摘要的话，收藏夹里躺着的是无法核对的转述 —— 这个项目的底线是每条结论都能回到出处
- **接口只收 id，正文由后端回 `chats` 取**（连带着把上一条用户提问也捞出来）。信前端传来的正文，收藏夹就能塞进任何一句话
- 按人存，和关注列表同一个文件（`saved` 键），上限 24 条；空列表不落盘、不留空壳；删会话时 `purge_thread()` 一并清掉，不留点开是空白的死条目
- 卡片进同一个网格，但**不冒充指标**：没有当期值、没有目标进度、点开也不是口径抽屉，所以左上角挂「问答」标签，正文是「问过什么 / 答了什么」。起初它是卡片下面一段虚线清单，结果看着像另一个板块，人不会认为那是自己的关注
- 计数合成一行 `6 / 8 指标 · 1 收藏`，但**不并成一个分母**：指标 8 个、收藏 24 条，混着算会让一条收藏挡住第 9 个指标
- 空的时候什么都不画，不写「还没有收藏」的占位

**关注动态**是规则归集，不是智能推荐。每条按「为什么冒出来」打一个分类标签，不是按颜色分（红黄只看颜色分不清是数落后还是时限紧）：

| 来源 | 分类标签 | 色标 | 点击去哪 |
| --- | --- | --- | --- |
| 指标低于年度目标 | 关注指标 | 橙 | 指标抽屉（口径、责任部门、报表名） |
| 督办事项 · 逾期/今日到期/临期 | 临近时限 | 红/橙 | 督办详情（可当场签收、反馈、办结） |
| 督办事项 · 签收超时/停滞 | 督办动态 | 蓝 | 督办详情 |
| 期次未披露 | 待披露 | 蓝 | 无，只提示 |

同一条事项可能同时命中「逾期」和「停滞」，按 `id` 去重。上限 6 条，取不满时显示实际条数 —— 不补假数据。**分管单位非空时，督办类动态只收自己分管的**，否则局长的「我的动态」里会冒出别的部门逾期，和下面「我跟进的」自相矛盾。

**未读**是真的读状态，不是「今天有几条」：`key = 类型:标识:正文指纹`，点一条就记一条，全部读过角标消失、「今日 N 条」回来。带正文指纹是必须的 —— 只拿 id 当 key，明天数值变了、事情催得更紧了，文字已经不同却仍显示"已读"。

**重点注意事项 · 我跟进的**按**分管单位**从督办台账派生，不另建一份"我要跟进"的名单：

| 身份 | 分管单位 | 这块里出现什么 |
| --- | --- | --- |
| 市长 | 空（全市） | 全市所有未办结事项 |
| 常务副市长 | 市发改委、市大数据局、市住建局 | 这三家主办或协办的未办结事项 |
| 市生态环境局局长 | 市生态环境局 | 生态环境局主办或协办的未办结事项 |

为什么不按人手点「跟进」：台账里没有"谁跟进"这个字段，凭空加一个就要有人维护，维护不动就会变成假数据。分管单位是身份自带的，台账里每条都有 `assignee` / `co_assignees`，两边对得上就是真关系，对不上就不出现 —— 不会编。

每行右侧是**进度条 + 百分比 + 剩余天数**，进度只认责任单位在事件流里报的 `percent`；没报过的写「未报进展」并留空进度条，**不拿状态折算成数字**（"待签收"折成 0%、"待审核"折成 100% 都是编）。排序按风险等级再按剩余天数，点一行进督办详情。

## AI 日程

顶栏「AI 日程」是**只读汇总**，不是日历。它回答两件事：今天必须做什么、下一件在几号。`/#cal` 可直达（打开后按当前身份现算）。

**为什么不做月历网格**：14 天里绝大多数格子是空的，一屏放不下，又看不出「下一件是几号」。按天分组的竖排时间线，同样面积能多放一倍信息。

**每一条都来自已经写进系统的时间**，不新建事实：

| 来源 | 变成什么 | 时间从哪来 |
| --- | --- | --- |
| 会议记录 | 会议 | `held_at`（有钟点；已结束的不排） |
| 督办事项 · 待签收 | 待签收（今天） | 状态机 |
| 督办事项 · 待审核 | 待审核（今天） | 状态机 |
| 督办事项 · 已逾期 | 已逾期（今天，注明原时限） | `deadline` + 剩余天数 |
| 督办事项 · 停滞 | 补报进展（今天） | 超过 7 天没有新进展 |
| 督办事项 · 未到期 | 办结时限（落在 deadline 那天） | `deadline` |
| 指标字典 | 数据披露 | `DISCLOSURE_DAY`（每月 10 日披露上月） |

**同一天只出现一次，不同天各算各的义务。** 一条事项今天要签收、20 号要办结，日程里就是今天一条签收、20 号一条时限 —— 这是两个义务日，不是重复。只有「今天到期且今天已经有动作」时才合并，否则同一件事会在同一屏出现两行。

**逾期不挂在过去的日期上。** 昨天已经过了，挂在昨天等于让它滚出视野；归到今天，并在说明里写「原定 X 日办结，已逾 N 天」。

**身份口径与工作台完全一致**（`core/people.py`）：分管单位派生 + 本人手动跟进。两边各写一套过滤，同一个人就会在工作台看到 5 件、日程看到 3 件，没人能解释差在哪。会议多一条规则：`host` 是职务（「常务副市长」）不是单位，除了参会单位还要拿本人的 `post` 比一次 —— 否则常务副市长看不到自己主持的会。

**AI 只写两句话，不排期**：一句今日重点、每条一行排序理由。模型拿到的是已经排好序的清单，不能新增事项、不能改时间。**出现清单外的数字整段丢弃**（和专家解读同一道数字闸），超过 80 字也丢弃。模型不可用或输出不合格时退回规则文案，页面标「按台账排序」，不假装是 AI 写的。

**明确没做**：

- **手工新建日程**。手工排期会变成第三份时间表（台账、会议记录、私人日历），迟早对不上。真要加，得先决定谁是唯一真相
- **在日程里签收 / 办结**。那等于又造一套状态机，和台账打架。点条目只跳回它的出处（台账详情 / 会议记录）
- **提醒推送本身不在日程里**。日程只解决「看得到」，叫醒是另一层的事（规则、闸门、通道），见「消息提醒」。两件事混在一个模块里，迟早出现「日程说今天没事、提醒却弹了三条」

## 材料助手

**它不是「AI 写材料」。** 汇报材料里最贵的错误不是句子不通，而是把「1—9 月累计」写成
「9 月单月」、把「预计」写成「实绩」、把去年的数当今年数。模型看到的是一串字符串，它没有
能力区分这些；而这类错误一旦写进上报材料，基本没人会回头复核——写的人自己也不确定。

所以反过来做：**骨架、段落、每个数字、每处出处都由代码装配**，模型只写最后一节。

三种骨架，数据来源是同一批：

| 骨架 | 章节 | 主要来源 |
|---|---|---|
| 工作汇报 | 指标运行 / 重点工作 / 会议落实 / 下一步 | 指标字典 + 督办台账 + 会议记录 |
| 会议落实材料 | 会议信息与交办明细 / 指标 / 披露情况 / 下一步 | 一场会议的记录 + 台账 |
| 督办通报 | 统计 / 逾期与临界清单 / 分单位办理 / 下一步 | 督办台账 |

**为什么叫「会议落实材料」而不是「会前材料」**：系统里只有已经开过的会（会后录入纪要），
没有「即将召开的会」。硬做会前材料就只能靠人手填议程，那又是一份和台账对不上的时间表。
所以这个骨架回答的是「这个会定的事，现在办到哪了」：交办事项已落库就带台账状态，没落库就
如实写「未落库」，不假装在办。

### 每处数字都带出处

指标表最后一列是「数据来源」，页脚按部门列出报表名与披露日；督办明细带台账编号；会议明细
标「台账」还是「会议记录」。测试里有一条硬断言：**材料里的指标值必须与问数接口逐字节一致**
——两份东西摆在一张桌上对不上，是最难看的一种错。

统计口径随身份收窄，并且写明「含协办」：局长协办的项目会算进他的台账，不写清楚就会出现
「统计 2 项、明细里却有别的单位」的印象。

### 模型只能写第四节

输入是一份已经排好序的事实清单（JSON），输出只允许 `{"next": "..."}`。三道闸：不超过 260
字、不得出现清单外的数字、不得新增事项或单位。任何一道不过就整段丢弃，页面上写明原因，退回
规则文本（规则文本也只用台账里算出来的数）。

模型写了之后，纸面上那行注释会跟着变成「本节由模型根据上文事实撰写」——不冒充，也不甩锅。

### 明确没做

- **不写讲话稿、不写工作总结**。那类文字没有可核对的数字锚点，写完也没法验证对错
- **不提供公文模板编辑**。版式写死在 CSS 里：让人自己调格式，很快就会调出四不像
- **不存档**。材料不落盘：一旦存起来就会出现「文件里的数和台账不一致」的问题，而那正是这类
  系统最容易失信的地方。要留存就导出 Markdown 或打印
- **纸张不跟随深色主题**。它是一张纸，屏幕上看到的必须和打印出来的一致

## 知识库

不是独立页面，是对话里的一个兜底：问「上次开会定了什么」「环保局那件事办到哪了」时，
由它接住。这类问题在指标字典里匹配不到任何指标，以前会被当成"没注册的指标"拒答——
而那恰恰是最容易回答的一类问题。

### 只收三类已有记录

| 来源 | 条目 | 出处 |
|---|---|---|
| 指标字典 | 11 个指标的定义、口径限制、责任部门、报表、目标 | `《本市统计月报》` 等 |
| 督办台账 | 每件事的标题、状态、协办、时限、风险 | `督办台账 DB2026-0033` |
| 会议记录 | 会议原文，以及每条议定事项在原文里的那句话 | `MT2026-0002` + 议定事项引句 |

**不新增任何录入动作**。索引是每次检索时从现有数据现算的（几十到几百条，成本可以忽略），
所以台账刚改完就能搜到，也不用处理缓存失效。

### 为什么不做向量检索

两条理由，第二条是决定性的：

1. 项目零第三方依赖，没有向量库。手写余弦在几百条上能跑，全市口径加历年事项上万条就退化，
   而且是那种"看着还能用、召回率悄悄掉一半"的退化，比直接报错更难发现。
2. **可核性**。向量召回的东西交给模型复述，模型会把甲文件的话安到乙文件头上。
   在公文场景里，这比答不出来严重得多。

所以检索由代码做，返回的**永远是一段真实存在的原文**。会议议定的引句必须逐字出现在
会议原文里，这条在冒烟测试里是硬断言（`引句逐字出现在会议原文中`）。指标口径条目
直接引用 `mockdata` 里的 `definition` 字段，不做任何"顺句子"。

### 检索怎么做的

中文没空格、标准库没分词器，引 jieba 就破坏了零依赖。做法是把问句和条目都切成相邻二字组
求覆盖率，再叠三层加权：

- **术语命中**：问句里出现指标别名 → 该指标口径条目 +0.55。用户念「规上工业」，指标名里一个字都没有
- **单位命中**：出现单位名（含简称和俗称）→ 该单位的事项 +0.30，并且在排序里优先
- **编号命中**：出现台账/会议编号 → +1.0

另有两道防误伤：二字组有 3 个以上时至少要命中 2 个（否则「火星基地建设情况」只对上一个
「建设」就算相关）；「事项」「单位」「情况」这类模板词不参与（台账每条正文里都有「责任单位：」，
留着会让所有条目一起虚高）。

**同义词是双向都试、取最高分**，不是单向替换：用户说「环保局」，要能匹配「生态环境局」；
但台账里写的就是「市发改委」，把它替换成「发展和改革委员会」反而命中不了。

### 什么时候介入

- **拒答之前**：指标一个都没匹配到，先查知识库，命中就答，不命中才拒答（拒答时会说清库里有多少条）
- **事项类话术优先**：问句里有「办到哪 / 进展 / 定了什么 / 谁在办」这类词，且知识库确实有
  督办或会议记录，就**不让问数答数值**。「环保局那件事办到哪了」曾经被答成「空气质量 86.5%」——
  答非所问，但形式上完全正常，看的人不会起疑，这是最坏的一种错
- 纯数值问题不受影响：「空气质量优良天数是多少」照常走取数和出处那一套

### 明确没做

- **指代消解**。「那件事」指哪一件，靠的是它周围的实词命中，不是真的理解上下文。
  只有一件事时能猜对，有几件同类型的事时会一起列出来
- **跨条目的推理**。「这两件事有什么关系」「哪个局欠的账最多」这类要算、要比的问题它不答，
  那是督办统计和材料的活

> 注：知识库这里的「文档上传」已经单独做成了「资料库」（见下一节）。本模块保持零依赖，
> 只检索系统自己产出的结构化记录；用户上传的任意文档走 `core/rag.py`。

## 资料库（通用文档 RAG）

上传任意文档 → 切块建索引 → 按问句召回相关原文片段。入口在设置 →「资料库」。

- **收什么**：md / txt / csv / tsv / json / html / docx / xlsx（复用 `docparse`，纯标准库解析）。
  PDF / PPT / 图片仍未接 —— PDF 是排版格式，取出的数字容易错行；图片要 OCR。
- **怎么切**：固定窗口 800 字符 + 120 重叠（照 octop 的 `chunk_text`）。
- **怎么存**：控制面进 `data/rag.json`（复用 `store.py`），原文落盘 `data/rag_files/`，
  每个库一个 SQLite 向量索引（`data/rag_idx/<id>.sqlite`）。SQLite 是标准库自带，不破零依赖。
- **怎么检索**：两档 —— 装了 `fastembed`（`pip install fastembed`）走本地 ONNX 语义检索，
  能召回"用词不同但意思相关"的片段；没装自动退回 bigram 关键词检索，功能照常。检索结果
  **永远是原文、带出处**，模型不转述、不碰数字 —— 与知识库、问数、纪要共用同一条边界。

向量化是可选增强，懒加载 + 静默降级，跟 `octop-memory` 一个套路：不装也能跑，装了自动升级。
- **权限**。它按演示身份收窄（和日程、工作台同一套口径），但身份本身仍是前端可切换的

## 消息提醒

顶栏「消息提醒」按开的那个面板，`/#notify` 可直达。它回答一个问题：**现在该叫醒谁，为什么是现在。**

### 三条边界

1. **不产生事实**。每条提醒带 `ref`，点开回到台账 / 会议记录 / 指标口径。正文里的天数、进度、期次全部从源数据取，不在这里算第二遍 —— 日程那边踩过一次：同一件事各算一次天数，就会出现「台账说逾期 3 天、日程说还有 1 天」
2. **不替代日程**。日程说「什么时候有什么事」，提醒说「现在要叫醒谁」。同一件事在日程里出现两行是 bug；在提醒里第二天再出现是正常的 —— 因为没办
3. **不预设通道**。站内信永远可用；桌面通知要浏览器授权；企微 / 邮件要填配置。**通道没配不等于功能没做**，页面上把「已送达」和「只在本机」分开写，不用一句「已提醒」把没发出去的说成发出去了

### 什么时候提醒什么

规则表就写在 `core/notify.py` 的 `RULES` 里，页面上那张表直接读它 —— 文案和实现分家比没有文案更糟，所以冒烟测试会检查每条规则都有对应的生成分支。

| 规则 | 什么时候 | 级别 | 发给谁 |
| --- | --- | --- | --- |
| 事项已逾期 | 逾期后每天一次（不受上班时间限制：已经出事了） | 紧急 | 责任单位 |
| 今日到期 | 时限当天 08:30 之后 | 紧急 | 单位 + 本人 |
| 交办未签收 | 交办满 24 小时后每天（08:30 之后） | 重要 | 责任单位 |
| 临近时限 | 到期前 3 天和 1 天各一次 | 重要 | 责任单位 |
| 进展停滞 | 停滞满 7 天后每周一 | 留意 | 责任单位 |
| 会议即将开始 | 开始前 60 分钟内 | 重要 | 本人 |
| 关注指标低于目标 | 新期次披露后（每期一次） | 留意 | 本人 |
| 期次待披露 | 披露日前 2 天 | 提示 | 本人 |

### 去重靠 id，不靠「发过没有」

提醒 id 是 `规则:对象:桶`，桶是日期（或期次、会议 id）。所以：

- 同一天同一件事只有一个 id → 不重复
- 第二天桶变了 → 自动重来一次（这才叫「每天提醒」）
- 已读只记 id，不改任何数据 → 标记已读不会让台账发生变化

跨天重置是免费的，不需要额外写一张「发送记录」表。

### 外发：四道闸，一道都不省

| 闸 | 为什么 |
| --- | --- |
| 只发紧急 / 重要 | 八条全推出去的结果是没人看，第二周机器人就被屏蔽 |
| 只发督办类 | 会议、指标、期次是给领导自己看的，推到单位群里是噪音 |
| 静默时段 22:00–07:00 / 周末只发紧急 | 半夜亮屏比不提醒更烦，也容易被当成系统异常 |
| 同批次不重发 + 日限额 20 条 | 定时任务每 5 分钟跑一次，没有幂等就是刷屏 |

批次指纹是「这批 id 的哈希」，不是条数 —— 换了一件事也是新信息，条数一样也该发。

### 通道怎么配

复制页面「送达配置」里的模板，存成 `config/notify.json`，重启服务。该文件已 gitignore（里面有 webhook key 和邮箱授权码）。

```json
{
  "channels": {
    "webhook": {"enabled": true, "url": "https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=…", "format": "wecom"},
    "smtp": {"enabled": false, "host": "smtp.example.gov.cn", "port": 465, "ssl": true,
             "user": "noreply@example.gov.cn", "password": "…", "to": ["zhuren@example.gov.cn"]}
  },
  "quiet_hours": ["22:00", "07:00"],
  "workdays_only": true,
  "daily_limit": 20
}
```

`format` 为 `wecom` 时按企业微信群机器人的 `msgtype=text` 发；为 `generic` 时原样 POST 一份带 `items` 的 JSON，方便接 OA。SMTP 用标准库 `smtplib`，不引第三方包。

也可以用环境变量（同名优先）：`OCGOV_NOTIFY_WEBHOOK` / `OCGOV_NOTIFY_WEBHOOK_FORMAT` / `OCGOV_NOTIFY_SMTP_HOST` / `_PORT` / `_USER` / `_PASSWORD` / `_TO` / `_SSL`。

**配置没有 HTTP 写入口**。写配置的接口等于给任何能打开页面的人改推送目标的能力，而这个项目明确没有鉴权 —— 与其加一个无鉴权的写入口，不如让人改文件。

### 明确没做

- **送达回执**。企微机器人返回 `errcode=0` 只说明「腾讯收下了」，不说明有人看了。要回执得走企业应用消息 + 已读回执接口，那是企业资质和 secret 的事
- **按单位路由**。现在一个 webhook 对应一个群。要「住建局的提醒只进住建局的群」，得配多组 webhook 并按 `assignee` 映射
- **短信 / OA 待办**。短信要通道商资质；OA 待办要各家 OA 的接口文档和 token
- **不提供强制群发**。`/api/notify/dispatch` 走全部闸门，没有 `force`。页面没有登录态，一个能强制群发的按钮等于把责任单位的群交给任何人

## 会议助手

顶栏「会议助手」按开的那个面板。它管两头：**会前**用一句话约会议（对话里出草稿，确认才落库），**会后**把会议记录抽成议定事项、交办进督办台账，`/#meeting` 可直达。

### 会前：一句话约会议

对话里说「下周三下午三点约个会，议题是冬季供暖保障，市住建局和市城管局参加，地点在3号楼会议室」，返回一张**草稿卡**，点「建会」才写库。

**这是两个实体，不是给会议助手加了个 if。** 现有 `create()` 要求纪要原文必填（没有原文就无从核对引文），`status=draft` 指的是「待解析」——都是会后。预约的会没有原文（还没开），状态是 `planned`（待召开）。所以 ledger 里加了 `kind`：`record`（会后记录）/ `plan`（待召开的会）。

**但它跟会议记录放同一个文件**，这是刻意的：日程和「会前 60 分钟提醒」读的都是 `list_meetings()` 的 `held_at`，只要进同一张表，那两处**一行都不用改**就能用。另起一个实体，日程和提醒就得各吃两套数据源，迟早对不上。

**为什么只出草稿，不直接建。** 两条理由，第二条比第一条硬：

1. 这个系统没有登录态（身份是右上角随时能切的演示身份）。对话里直接建会 = 任何打开页面的人都能以「市政府办」名义造一场会，而且会立刻进日程、进提醒。
2. **会议没有改字段的接口，建完只能删。** 所以能改的地方必须在确认之前——草稿卡里那几个输入框是唯一的修改机会，不是装饰。

**没说清楚的地方必须写出来。** 草稿卡上分两类：`missing`（缺必填，红字标出，缺着不许建）和 `assumptions`（我替你定了，黄字说明理由）：

| 情况 | 处理 |
| --- | --- |
| 只说「三点」没说上下午 | 按下午 15:00，并写明「没说上午下午，按下午算」 |
| 只给日期没给钟点 | 按 09:00 占位，写明「建会后请改」 |
| 没说哪天只说时间 | 今天这个点没过就是今天，过了就是明天，写明 |
| 没说谁主持 | 按当前身份的职务填，写明「可以改」 |
| 「周三」而本周已过 | 取下周三，写明 |

时间解析按**周一为一周起点**（国内习惯），所以「下周三」永远落在下周一之后，不会有跨周歧义。支持 `11月20日`、`下周三`、`后天`、`月底`、`下午2点半`、`14:30` 这类说法；算出来的时间已经过去时会单独提示「确认一下是不是说错了」。

**参会单位按台账里真实出现过的单位匹配**（责任人 ∪ 协办 ∪ 演示身份分管单位 ∪ 已有会议参会单位，现算不落盘，当前 14 个）。只做「去行政级别前缀」这一种归一（`住建局` → `市住建局`），**不做编辑距离**：「生态环保局」和「市生态环境局」差三个字，编辑距离会把它们算成同一个，但那是猜——猜错的单位会收到一场不属于它的会。台账里没有的，原样保留并标出来，不硬塞进白名单。

**撞车只能说「同一时间段还有另一场会」。** 系统里没有人员日历，也没有会议室资源，所以做不到「张局长那个点没空」。硬说能查，等于让人以为系统知道他不知道的事。

**重复点只建一场。** 幂等键是 `from_message`（`会话:消息`），刷新页面后那张卡也不会变出第二场会；`GET /api/threads/<id>` 回放时会补上 `meeting_id`，卡片直接显示「已建会」。

### 明确没做（会前这一半）

- **不外发会议通知**。约好的会只进日程和会前 60 分钟提醒，不发企微、不发邮件。现有 notify 的四道闸只放行督办类，扩到会议通知要单独定规则（发谁、发几遍、取消后怎么撤回），这一轮没做。
- **不能改会**。建完之后只能删了重建——所以确认前的草稿卡才是唯一的修改点。
- **没有参会人回执**。谁收到、谁来不了，系统一概不知道。

### 为什么是这个形态，而不是接腾讯会议

查过 octop 的源码：它**没有会议助手这个功能**，只有一条连接器目录项（`src/octop/infra/connectors/catalog.py:157`，`kind="tencent-meeting"`，描述「会议管理、查询、录制与智能纪要」）和把它拼成 MCP 规格的 builder（`src/octop/infra/connectors/builder.py:153` → `https://mcp.meeting.tencent.com/mcp/wemeet-open/v1`，头 `X-Tencent-Meeting-Token`）。没有 router、没有表、没有页面。它做的是「把腾讯会议当一个 MCP 挂进来，交给通用智能体去用」。

所以这里没有"照抄一个现成实现"的可能。能做的是判断：政务场景里会议助手真正的价值不在「看会议列表、看录制」，而在**会议议定的事有没有人办、办到什么程度**——这正好接上已有指标与督办闭环。腾讯会议那条路留了口子（`core/meeting/ledger.py` 的 `source` 字段就是为此留的），但要 token，本机没有，也不该假装打通。

### 三道闸：模型不许编

纪要抽取和问数的风险完全不同。问数是「模型只出查询计划，数值由接口给」，模型没有机会编数字；纪要抽取是**让模型直接从自然语言生成责任单位和时限**，它编出来的「11 月 20 日前完成」会直接变成督办时限。

所以 `core/meeting/extract.py` 设了三道闸，全在服务端：

| 闸 | 判据 | 不过时 |
| --- | --- | --- |
| 引文闸 | 每条必须给 `quote`，归一化后必须是原文的连续子串 | `quote_not_found` |
| 数字闸 | 标题 / 办结标准里的阿拉伯数字、时限的月与日，都必须能在原文里找到 | `number_not_in_source`、`deadline_not_grounded` |
| 白名单闸 | 责任单位只能取自**实际存在过的**单位（督办台账 ∪ 指标责任部门，当前 22 个） | `unknown_unit` |

引文闸是关键：模型没办法靠「理解大意」蒙混，它必须真的指着原文说话。原文只写「年底前」，模型就别想给出 12-31 —— 实测里这条确实被拦下，标成 `deadline_missing`（`needs_review`）。

### 人工认领：校验不该反过来卡人

红线是**别让人被自己的规则锁死**。最初版本里，人工把「年底前」补成 12-20 之后，系统仍然说「原文里没有 12 月」，这条就永远落不了库。

所以问题分两类：**硬问题**（引文对不上、字段为空、时限已过期、单位不在名单）谁改都要重新满足；**软问题**（`deadline_not_grounded`、`number_not_in_source`）本质是「疑似模型编的」，允许人工认领——人改过哪个字段，就豁免哪个字段的软校验，并在 `verify.confirmed_by_human` 里留痕，界面上显示「人工设定 deadline」。

理由：他在这个界面上改字段，本身就是在承担责任。审计要的不是「拦住人」，而是「谁定的、留得下来」。

### 解析和落库是两步

`POST /parse` 只做抽取和校验，`POST /commit` 才写督办。中间那一步人工勾选不能省：

- 只有 `verify.status == "ok"` 的条目才能勾选；标红的要先把字段改好
- 混入任何一条未通过的，**整体拒绝，一条都不写** —— 督办台账是有人真要去办的东西，半截写入比不写更难收拾
- 已落库的事项不能重新解析（会打乱台账里的事件链），也不能再改（请去督办台账操作）
- 引文 `quote` 不可编辑：人能改引文，等于能把校验关掉

落库后条目会出现在罗盘底部预警条和个人工作台的关注动态里，来源写的是「会议：<会议标题>」，来源文号是会议编号。事项旁会挂上台账编号（如 `DB2026-0036`），**点它直接跳到那条督办事项**，页头留「← 会议助手」原路返回——不用回罗盘从预警条里翻。

### 督办台账的三个入口

| 入口 | 位置 | 说明 |
|---|---|---|
| 预警条「进入统筹推进」 | 罗盘底部 | 唯一的总入口，常驻（没有预警也在），逾期数角标挂在条标题上，来自 `/api/overview` 的 `oversight.overdue` |
| 预警条里单条事项 | 点标题 | 直接定位那条，不是打开列表 |
| 会议助手里的台账编号 | 已落库事项的标签 | 跳转并带返回；目标若已办结会自动切到「已办结」筛选 |

顶栏原有一个「统筹推进」常驻按钮，已撤掉：它和罗盘底部的预警条指向同一个台账，两个入口反而让人以为是两套东西。角标信息没有丢，挪到预警条标题上了。

### 明确没做

- **不接录音转写**。本机没有 ASR，页面也不假装能听音视频；要先转成文字再粘进来
- **不直连腾讯会议 MCP**（见上面）
- **没有"AI 生成纪要"**。会议记录原文是输入，不是模型产物 —— 让模型写纪要再让模型抽事项，等于自己给自己出题自己判卷
- **会议助手本身不出材料**。按会议汇总指标与交办明细在「材料助手」的「会议落实材料」骨架里；这里只管记录、抽取和落库，一件事只有一个地方做

## 督办闭环

会议落库的终点就是督办的起点：一条事项进了台账，后面全是「谁签收、办到几分、拿什么证明办完了」。

### 状态机只有 6 个动作

```
待签收 ──签收──► 办理中 ──提交办结──► 待审核 ──确认办结──► 已办结
                    ▲                     │
                    └────────退回─────────┘
催办：待签收 / 办理中 / 待审核 都可以，但不改状态
```

守卫集中在一个函数（`_guard()`），规则是：

- **状态不对一律拒绝**：不能跳步（`待签收` 直接 `确认办结`）、不能重复（连点两次签收）
- **提交办结三件套**：至少一条进展记录 + 办结说明 + 佐证材料。缺任何一样都拒，并把缺的那一条写进错误信息
- **退回必须写理由**，否则责任单位不知道该补什么
- **催办不算进展**。`last_activity` 明确排除催办事件——否则天天催办的事项永远不会被判"停滞"，等于用催办把问题刷绿

被拒绝的请求返回 `ok=false` + 中文原因，且**不落任何数据**。前端不预判能不能点，按钮按 `allowed_actions` 渲染，点下去让后端判——两套规则一定会漂移，所以只留一套。

### 强制和宽松的分界

会议助手那边有"人工改过的字段豁免对应软校验"的机制（见上文「人工认领」），督办这里**没有**：流转守卫是硬的，改不了、绕不过。

理由不同：会议事项是**从自然语言里猜出来的**，猜错了该让人修；督办流转是**人对系统的正式表态**，签收了就是签收了，不能有"我改一下让它通过"的路径。

### 批量催办不原子

会议落库是"任一条不通过就整体拒绝"，因为写一半的台账更麻烦。批量催办反过来：**逐条执行、逐条报结果**。

催办只是往事件流里记一条提醒，部分成功没有副作用，硬要原子性只会让能催的也催不出去。返回里 `urged` 和 `failed` 分开列，失败的带原因（已办结不能催 / 事项不存在 / 状态不允许）。

### 并发

`_ITEMS` 是进程内 dict，`ThreadingHTTPServer` 是多线程的。一次流转要「读状态 → 判守卫 → 改状态 → 追加事件 → 落盘」，中途被别的线程插进来会出现两条签收事件或者状态回退。所以 `advance()` 和 `create_item()` 整段包了一把模块级 `RLock`（可重入，因为内部还会调 `get()` / `assess()`）。

注意这**只解决单进程内的并发**。起两个 worker 共享 `data/*.json` 仍然会互相覆盖，要多人用必须换 SQLite/PostgreSQL。

### 技能与 MCP：哪些能复用，哪些不能

经常被问「octop 那边现成的 skill / MCP 能不能直接拿过来」。四类都核过源码：

| 东西 | 位置 | 能不能用 | 为什么 |
| --- | --- | --- | --- |
| octop 插件（`kind: tool/skill/hook`） | `octop/octop-dashan/plugins/demo-*` | 不能 | `main.py` 里 `from octop_harness.plugins import PluginContext`，是 octop 运行时的插件。oc-gov 没有这个运行时，塞进来等于引第三方依赖 |
| octop 的 MCP 原型 | `octop/octop-dashan/prototype/{metrics-qa,oversight}/mcp_server.py` | 只搬设计 | 用的是 `from mcp.server.fastmcp import FastMCP`（官方 SDK）。工具签名和描述文案可以直接搬，代码要按标准库 JSON-RPC 重写 |
| octop 的通道 | `docs/discord-channel.md` | 不能 | 走 `octop-gateway` 适配器，是外部包。可借鉴的只是形态：通道 = 独立配置 + 连通性检查 + 单实例 |
| 本机 MCP（github / lighthouse-ops / annolab / graphify） | `~/.workbuddy/mcp.json` | 与业务无关 | 部署、代码托管、图像标注，跟政务工作台不是一件事 |

所以这一版**没有引任何 MCP 客户端**，也没抄一行插件代码。要用 MCP 得先回答「谁调谁」：

- **oc-gov 当 client 调外部工具**（比如查政策库、查企业信用）：零依赖下要手写 stdio JSON-RPC，收益是有的，但当前没有这个需求；
- **oc-gov 把能力暴露成 server 给 agent 调**：`core/*` 已经是纯函数，包一层就够。但 `commit_items` / `advance_oversight` 是写操作，必须单独鉴权，不能和只读工具混在一张表里放出去 —— 让模型自己判断要不要遵守状态机守卫，等于没有守卫。

真正值得复用的是**方法论**，不是代码：本机 `~/.workbuddy/skills` 里的 `verify-tests-by-mutation`（证明新加的断言真能抓到 bug，而不是摆设）和 `local-llm-behavior-eval`（给「模型输出闸门」做可复现评测）。这个项目的闸门特别多（数字闸、长度闸、引文闸、知识库命中闸），值得照那套做法补一层评测。

### 刻意不照搬的

| octop 的做法 | 这里的选择 | 理由 |
| --- | --- | --- |
| LangGraph 的 function calling 循环（模型可连续调工具、自主拆解） | 保持「模型只出查询计划，程序取数」 | 一套能生成数字的模型，就多一条编数字的路径。这个项目的安全边界不能破 |
| WebSocket + hub/subscribe/active_turns 断线重连 | SSE | 标准库手写 WS 握手代价高、收益为零；单机演示不需要「断开不杀任务」 |
| `thread_history_projection` 双来源（投影 + checkpoint） | 只有一份存储 | 那是兼容老数据的迁移产物，新项目不需要 |
| `trajectory_events` 观测表 | 不建 | 与对话正确性无关，需要时再加 |
| 按员工分配模型（`user_policies` + revision CAS） | 不做 | 单机单用户；做多租户时再补，`filter_refs` 那几行可以直接抄 |


## 下一步（按依赖顺序）

0. **给智能体用的三种交付形态**（项目既定方向）—— 现在的 `core/*` 已经全是无 HTTP 依赖的纯函数，可以按下面三层往上包：
   - **MCP 服务**：把已有能力暴露成工具，例如 `query_metric(code, period)` / `search_knowledge(q)` / `scan_oversight(days)` / `extract_minutes(text)` / `commit_items(meeting_id, ids)` / `advance_oversight(id, action, text)`。标准库就能写 stdio JSON-RPC，不用引 SDK。**注意 `commit_items` 和 `advance_oversight` 都是写操作**，要么单独鉴权，要么只暴露读和解析（`query_metric` / `scan_oversight` / `extract_minutes`）——让智能体自由调用写工具，等于把状态机守卫交给它自己判断要不要遵守
   - **Skill**：把「怎么问指标」「怎么从纪要抽事项」的调用顺序固化成说明文档 + 示例，让智能体不用每次重新摸索
   - **专家团**：现在只做了「解读型」的一层（角色卡 + 不带数字的定性分析，见上文），**还没有工具子集**。真正要做的是让指标问数、督办闭环、会议纪要三个角色各自绑定自己的只读工具，互相之间不共享写权限
1. **真实数据接入** —— 换 `mockdata.py`，同时补接口超时、脏数据、口径突变的处理。这是唯一能让页面从「演示」变「能用」的一步
2. **权限** —— 市领导 / 分管领导 / 委办局三档可见范围，按部门和角色做行级授权，并记审计日志（谁、何时、问了什么、看到哪些字段、替谁签收）。会议助手和督办台账让这件事更急：现在谁能打开面板谁就能把事项写进台账、还能替任何单位签收（`actor` 只是前端传的一个字符串）
3. **通知（第一段已落地，剩下的是接真通道）** —— 规则表、跨天去重、四道闸、站内信、浏览器桌面通知、企微群机器人 / SMTP 的外发骨架都做完了，见「消息提醒」。剩下三件都不是代码问题：企业微信应用消息的 `corp_id` + `secret`（群机器人 webhook 只有群消息，没有已读回执）、按单位配路由（一个 webhook 一个群）、OA 待办的接口文档。短信还要通道商资质
4. **会议通知** —— 约好的会要能发到参会单位（企微 / 邮件 / OA 待办），以及取消或改期时怎么撤回已发的通知。和上一条共用通道，但规则不同：提醒是「催你办」，通知是「通知你来」，发错了比没发更麻烦

5. **指标中台** —— 指标注册、口径版本、责任部门维护、同源同口径校验。没有这层，指标只能硬编码在代码里
6. **公文模板** —— 材料助手的版式现在写死在 CSS 里。真要对接各单位的公文格式（字体字号、行距、红头、版记），得把版式抽成配置，并且配一个校对工具，否则同一个市里每个局交上来的材料长得都不一样
7. **政策文件库的接入打通** —— 「资料库」（`core/rag.py`）已经能上传文档、切块建索引、召回原文。剩下的是把它**接进问答链路**：问数时先查指标库，未命中或检测到"文档问题"时走资料库检索原文。以及向量化的后补：现在靠 bigram 兜底，装 `fastembed` 后自动升级为本地 ONNX 语义检索，能召回"用词不同但意思相关"的片段
8. **民情焦点** —— 接 12345 工单聚类
9. **上政务专网前**：模型换内网推理（vLLM / Ollama + 本地权重），关掉联网搜索和外网连接器，接口加鉴权与留痕
